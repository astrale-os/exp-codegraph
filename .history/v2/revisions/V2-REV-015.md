# V2-REV-015: Extract Codegraph and distribute native analysis as opaque platform artifacts

Status: accepted

Date: 2026-08-15

Affected requirements: V2-TS-001, V2-TS-002, V2-TS-013, V2-MIG-004, V2-QLF-002, V2-QLF-005, V2-QLF-009, V2-QLF-010

Review perspectives: Codegraph product, analysis/native, consumer/DX, qualification/release

## Existing decision

The original ADR kept TypeSpec V2 in one published JavaScript package during migration and required
ordinary consumers to receive built native binaries without Go. The implementation still resolved
its compiler-near analyzer through `ttsc`'s source-plugin cache, shipped `ttsc` as a runtime
dependency, and therefore carried a bundled Go toolchain into ordinary installations. The ADR did
not define a multi-platform artifact format, validation boundary, or failure contract.

The architecture has since been extracted from Kernel as standalone Codegraph. The consumer package
is `@astrale-os/codegraph`, its CLI is `cg`, and Kernel is a downstream consumer and qualification
corpus. Historical TypeSpec wording remains useful architectural history and is not mass-rewritten.

## Proposed decision

`@astrale-os/codegraph` remains the sole supported consumer library and CLI package. Native
executables are delivered by exact-version, OS/CPU-filtered optional artifact packages named
`@astrale-os/codegraph-native-<platform>-<architecture>`. These packages are opaque delivery units:
they expose no JavaScript API, cannot become semantic dependencies, and contain only one executable,
its manifest, license, and third-party notices.

The initial supported target set is Darwin and Linux on x64 and arm64. Windows is deliberately
deferred until it has its own native and packed-install qualification rather than carrying an
untested `.exe` branch. Each release records
all artifacts in one versioned root manifest containing the Codegraph version, protocol and compiler
toolchain revisions, target, artifact package, executable path, byte length, and SHA-256 digest.

Runtime resolution is fail-closed and ordered:

1. an explicit application-controlled binary;
2. the matching installed artifact validated against the root and artifact manifests; or
3. a stable actionable error.

There is no production source-build fallback, postinstall compilation, runtime download, PATH
discovery, or silent selection of an unqualified binary. `ttsc`, TypeScript-Go, and Go remain
development/release inputs only. A separate explicit developer build command may produce a local
binary, which applications then select through the same explicit-binary boundary.

## Evidence and motivation

The source-level release audit found that the Darwin arm64 `ttsc` installation retained a bundled Go
toolchain and that the existing no-local-Go test proved only the absence of a system Go executable.
The package had no platform matrix, artifact manifest, digest resolver, packed-install execution
test, or negative scan for compiler/build inputs. That is not the ordinary-consumer contract required
by V2-TS-013.

Platform artifact packages preserve one consumer journey while allowing package managers to install
only the current target. Exact manifests make selection deterministic and independently auditable.

## Alternatives

- Put all four binaries in the root package. Rejected because every consumer would download every
  platform and architecture.
- Download a binary on first use. Rejected because runtime network access weakens reproducibility,
  offline operation, provenance, and the package-manager trust boundary.
- Compile in `postinstall` or on first analysis. Rejected because ordinary consumers would still
  require a compiler toolchain and installation would execute build code.
- Keep implicit `ttsc` cache compilation only for source checkouts. Rejected because source versus
  packed behavior would be an ambient physical-path branch. Developer builds must be explicit.
- Publish four consumer libraries. Rejected because artifacts own no API or semantics; the single
  Codegraph package and its public subpaths remain the supported product boundary.

## Compatibility, migration, and gate effects

The old `ttsc-cache` resolution origin is removed rather than deprecated. Internal application
composition migrates to the distribution resolver in one cut. Existing callers that deliberately
provide an explicit qualified binary continue through the explicit-binary contract.

V2-TS-013 remains unqualified until every supported target builds and executes on its native runner,
the assembled root manifest validates all artifacts, and a packed consumer succeeds with `ttsc`, Go,
source plugins, lifecycle scripts, and network access absent. Gate 6 remains open until those proofs,
self-hosting, performance, and negative scans all pass.

## Objections and dispositions

- Product objection: companion packages conflict with the one-package ADR. Resolved by keeping one
  public consumer package; companions are opaque package-manager artifacts, not libraries or public
  subpaths.
- Analysis/native objection: a manifest cannot prove semantic compatibility alone. Resolved by
  retaining exact compiler/protocol revisions and rerunning native semantic qualification on every
  artifact before assembly.
- Consumer/DX objection: optional dependencies can be omitted or pruned. Resolved by stable errors
  naming the exact target/package and by preserving explicit binary selection for controlled hosts.
- Qualification objection: cross-compilation could hide target defects. Resolved by building and
  executing each artifact on a native hosted runner, then installing the packed consumer separately.
- Security objection: package presence is not enough. Resolved by version, containment, regular-file,
  executable-mode, byte-length, and SHA-256 validation before spawn.

## Consensus and decision

Accepted under the user's direction to extract Codegraph cleanly, avoid runtime dependence on
`ttsc` machinery already used only as a compiler substrate, and complete the release boundary rather
than treating source-cache compilation as packaging. All four perspectives agree that opaque
platform artifacts preserve the one consumer API while satisfying the no-Go production contract.
