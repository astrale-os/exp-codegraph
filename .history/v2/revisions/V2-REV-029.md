# V2-REV-029: Make explicit specification bindings the module conformance authority

Status: accepted

Date: 2026-08-24

Affected requirements: V2-APP-001, V2-APP-002, V2-APP-004, V2-CON-001, V2-CON-002,
V2-CON-003, V2-CON-005, V2-MIG-002, V2-MIG-004, V2-QLF-003, V2-QLF-006, V2-QLF-009

Review perspectives: specification authority, TypeScript semantics, application and persistence,
dependency policy, failure and observability, incremental correctness, performance, maintainability

## Existing decision

V2-REV-028 retained the native implementation-surface graph and recursive structural comparator as
the verification oracle while placing an explicit binding experiment before further specialized
optimization. The request-planned corpus compiler, source admission, compatible compiler universes,
incremental generations, and atomic fact shards were deliberately verifier-model-neutral.

The experiment established that verification can instead compile the authoritative `.spec/api.d.ts`
and implementation entrypoint in the same TypeScript project, enumerate exact exports, require type
exports to resolve to specification identities, and prove runtime namespaces through an explicit
owner-local `implementation.contract.ts` `satisfies` statement. Direct compiler-resolved dependency,
package-intent, error-code, ownership, and diagnostic evidence fits in small owner-addressed facts.

## Decision

- Compact explicit module-binding facts are the sole evidence capability for the structure, surface,
  and dependency conformance profiles.
- `.spec/api.d.ts` remains normative. Type exports bind explicitly to its symbols. A module with
  runtime exports owns `implementation.contract.ts`, importing the specification namespace as type,
  importing the implementation namespace as value, and applying `satisfies typeof contract`.
- Exact export enumeration is bidirectional. Missing, undeclared, namespace-mode, type-identity,
  runtime-binding, TypeScript, expected-error-code, deep-import, unowned dependency, and package
  authority findings remain explicit diagnostics.
- Verification does not independently reconstruct a complete implementation declaration graph,
  normalize two transitive graphs, or invoke the native module-surface producer as fallback.
- Binding facts are stored once per owner as content-addressed shards within one atomic observation
  generation. Timings and resident memory are telemetry, never semantic identity.
- Implementation changes invalidate their most-specific binding owner and qualification. Unknown
  change evidence widens to all requested binding owners. Unchanged shards remain retained.
- Compatible TypeScript projects execute serially inside bounded worker processes. Worker failure,
  fallback count, phase time, and peak resident memory are visible. Whole-corpus fallback is zero.
- The deleted comparator, contract compiler, and their legacy-shaped tests are not retained behind a
  version flag. General TypeScript analysis remains available only as a distinct capability for its
  independent consumers.

Binding fact vocabulary is owned by `analysis/binding`; TypeScript binding execution is owned by
`compiler`; application observation orchestrates atomic materialization; and conformance depends only
on analysis evidence. The application-to-compiler and compiler-to-analysis edges are explicit and
acyclic.

The maintainability budget's numeric ceilings are unchanged. Its locked optimization-import allowlist
adds only the materializer-to-binding-worker edge, the specification compiler-to-process edge, and
the process-to-worker URL reference; the measurement gate now recognizes that explicit dynamic
worker ownership and excludes Git-reported deleted paths from worktree reads.

## Compatibility and migration

This is a deliberate conformance authority change, not a diagnostic-suppression optimization.
Repositories migrate implementation owners to explicit type re-exports and runtime contract files.
Until migrated, verification reports the exact missing bindings and remains non-passing; it does not
silently accept structural resemblance. Profile identities remain stable and profile version 3
records the changed evidence contract.

Old analysis generations are regenerable acceleration and miss by capability identity. Historical
qualification evidence remains immutable history, but the executable recursive comparator and its
checkpoint transport are not part of the active verifier.

## Qualification evidence

Focused compiler and conformance tests prove positive bindings, missing and undeclared exports,
type/runtime drift, error-code evidence, dependency policy, partial-evidence failure behavior,
bounded worker reporting, and atomic materialization. Existing application incremental tests prove
generation-pinned reuse and selective qualification.

On the governed Kernel revision `bfe6be8e7964f3d9d8b0b9d932802bd4d1cd740b`, final V0 selected-cold
qualification materialized 169 binding facts with a maximum 149,040-byte fact, zero native work and
zero fallback, 573.66 MiB parent peak RSS, and 623.28 MiB maximum compiler-worker RSS in 9.79
seconds. Final whole-corpus V1 materialized 356 facts with the same maximum fact size, zero native
work and zero fallback, 492.94 MiB parent peak RSS, and 754.17 MiB maximum compiler-worker RSS in
60.22 seconds. These bounded representation results do not graduate the lightning-cold target and
are retained as honest remaining-performance findings, not relabeled as success.

V2 changed `backend/index.ts` beneath the most-specific binding owner and compared every resident
result with an independent dirty cold projection. Three isolated samples updated exactly one shard
with one compiler Program, had exact binding and application semantics, and completed in 3.395,
2.182, and 2.157 seconds: 2.182-second median and 3.395-second maximum. V2 therefore qualifies the
below-three-second median and below-five-second immediate gates without trusting the changed-path hint
as identity.

## Consensus

Accepted through the maintainer's explicit 2026-08-24 direction to migrate properly, not keep the
legacy verifier, preserve correctness and observability, avoid unbounded memory use, and converge
without further speculative optimization.
