# V2-REV-028: Make Codegraph checks request-planned proof-carrying products

Status: accepted

Date: 2026-08-22

Affected requirements: V2-ANA-002, V2-ANA-005, V2-ANA-007, V2-ANA-012, V2-ANA-013, V2-APP-001, V2-APP-002, V2-APP-003, V2-CON-001, V2-CON-003, V2-CON-004, V2-REP-001, V2-REP-005, V2-SEC-001, V2-SEC-003, V2-QLF-003, V2-QLF-006, V2-QLF-007, V2-QLF-009

Review perspectives: Codegraph product and API, specification and TypeScript semantics, application and persistence, consumer and DX, security and failure, qualification and performance, maintainability and observability

## Existing decision

V2-REV-027 established an exact application delta, advisory workspace checkpoints, and immutable
content-addressed analysis generations. V2-REV-022 established exact demand-driven native namespace
projection. Those foundations make incremental and portable reuse possible, but the ordinary check
path still constructs a complete application corpus before it resolves the request.

On the current governed Kernel corpus, a selected cold check takes about 85 seconds and an ordinary
private specification documentation edit takes about 85 seconds even after a successful preceding
check. Compilation accounts for about 89 of 95 instrumented seconds. Repository statistics consume
another 2.5 seconds despite contributing no ordinary `cg check` diagnostic. The application
checkpoint that should reopen the corpus is not published because a diagnostic object contains an
explicit `undefined` optional field; publication catches the error and exposes it only to an
optional telemetry sink.

Cold verification has a separate representation failure. Module facts embed repeated declaration
closures and the native producer constructs one approximately 599 MiB decoded transaction. The
bounded protocol correctly rejects it at the governed 384 MiB semantic-payload limit. Raising that
limit would preserve the representation defect and weaken the memory boundary.

## Decision

- The canonical source/compiler path remains semantic authority. Every accelerated result must be
  exactly equal to `canonicalSlow(source, engine, request)` in diagnostics, ordering, exit status,
  failure class, identities, selected/support closure, and observable side effects.
- A check request is planned before expensive compilation. Discovery produces a bounded ownership
  and dependency index; selection determines the exact required closure; compilation, observation,
  and qualification execute only that closure. Uncertainty widens visibly to the canonical complete
  path.
- Repository statistics become an explicit application capability. Ordinary `cg check` does not
  request them. Consumers that need statistics receive the same exact report under a deliberately
  different capability-bound application identity.
- Specification compilation gains a bounded shared-corpus session. It shares parsing, module
  resolution, and safe declaration state across owners while retaining an isolated canonical
  fallback for an owner whose ambient behavior cannot be proven safe. Shared and isolated results
  must be byte-semantically identical.
- The Node application may admit a Git-backed `SourceProof` using the installed `git` executable as
  its authoritative Git adapter. A clean proof binds repository format, object format, HEAD tree,
  and source-scope rules. A dirty proof adds sorted Codegraph-digested overlay records for changed,
  deleted, untracked, symlink, executable, and submodule inputs. Conflicts, unreadable inputs,
  unstable reads, unsupported repositories, ignored semantic inputs, or uncertain parsing produce
  an attributed complete-scanner fallback.
- Git object details remain inside the Node adapter. Portable application and workspace layers
  consume only an opaque proof identity and changed-path evidence. Absolute paths, branch names,
  inode numbers, and timestamps never enter semantic identity.
- A semantic pack is an immutable, portable, content-addressed manifest over source proof, producer
  components, configuration, profile, ownership, specification, observation, qualification, and
  optional analysis shards. It is untrusted acceleration: incomplete, stale, corrupt, incompatible,
  oversized, or mismatched packs produce a visible miss and the canonical path.
- Public TypeScript declarations are stored once as content-addressed declaration shards. Module
  facts reference declaration identities rather than embedding repeated transitive payloads.
  Requested module owners are projected on cold and incremental runs. Native results are staged as
  bounded shards and become visible through one atomic manifest; the 384 MiB semantic transaction
  limit remains unchanged.
- Checkpoint and semantic-pack publication failures remain semantically advisory, so they cannot
  change a successful check result. They are nevertheless observable through a required structured
  lifecycle receipt that the CLI qualification records. `dispose` drains publication and returns or
  throws only for lifecycle misuse; ordinary cache failure is a typed receipt, never an unhandled or
  silently discarded defect.
- Performance-specific mechanics live in owner-local `*.optimization.ts` files when they are not
  required for correctness. Correctness owners expose small substitutable contracts and may not
  import their optimization implementation. Architecture qualification enforces this dependency
  direction and repository complexity ratchets.

## Qualification constitution

Every performance claim is subordinate to the exact canonical oracle. Qualification records raw
argv, process identity, source and producer proof, request, output digests, exit status, causal work
counters, cache/pack provenance, phase durations, peak RSS, and the harness identity. An independent
verifier recomputes the receipt digest and all derivable predicates.

The honest start classes are:

| Class | Starting state | Hard target |
| --- | --- | ---: |
| C0 replay | Exact admitted result transcript exists | every run below 1 second |
| C1 workspace-cold | Empty local cache and matching portable semantic pack | every run below 3 seconds; p95 below 2.5 seconds |
| C2 delta | Prior exact checkpoint or pack plus one private owner edit | below 5 seconds first; graduate below 3 seconds |
| C3 genesis | Source only, no local or supplied semantic artifact | separately measured; graduate below 3 seconds on governed Kernel |

Selected C3 work is proportional to the selected closure. Whole-workspace C3 may graduate only
after the shared corpus compiler satisfies the same canonical oracle. C1 pack production is outside
the timed check and must occur in a distinct process and absolute path.

The verify classes are:

| Class | Required result |
| --- | --- |
| V0 selected cold | Requested owners only, below the 384 MiB transaction limit |
| V1 whole cold | Complete canonical facts, bounded staged shards, no monolithic transaction |
| V2 incremental | Affected shards only and exact equality with an independent cold projection |

Capability regressions are checked from a frozen externally stored contract manifest, not from the
candidate's self-report. Hidden holdouts cover valid and diagnostic sources, selection shapes,
create/delete/rename/revert, configuration, package authority, layouts, tests, symlinks, executable
modes, submodules, ignored and untracked inputs, corrupt packs, concurrency, cancellation, and
TOCTOU mutation.

Maintainability qualification records production physical LOC, source file and directory counts,
largest files, files above ratcheted size bands, dependency cycles, and repeated boundary guards.
The first accepted receipt freezes the baseline. Later changes may improve it or consume an explicit
reviewed budget; they cannot reset the baseline from the candidate tree. Small files are preferred,
but empty wrappers, dense compression, or fragmented files without semantic ownership do not count
as improvement.

## Implementation DAG and recovery

The executable roadmap is recorded in the root `TODO.md`. Its nodes are independently reviewable and
retain the canonical miss path. A node may be retried after a classified defect, split into smaller
children, or take its documented fallback edge. Repeating an identical failing action without new
evidence is prohibited. A blocked optimization never blocks correctness work, observability work,
or another independent DAG branch.

## Evidence and motivation

The current exact-origin Kernel measurements are:

- selected backend cold check: 85.50 seconds;
- identical selected replay: 0.89 seconds;
- selected check after one private specification documentation edit: 84.78 seconds;
- whole cold check: 100.69 seconds;
- whole identical replay: 0.71 seconds;
- instrumented selected refresh: 94.56 seconds total, including 89.36 seconds compilation,
  1.27 seconds inventory, 2.52 seconds statistics, 0.98 seconds analysis, and 0.34 seconds
  qualification; and
- selected backend verify: 899.74 seconds before rejection at 628,045,875 decoded semantic bytes
  against the 402,653,184-byte limit.

These measurements show no mathematical lower bound near the observed duration. Exact source-only
admission must examine every uncertain input, but Git tree objects and a dirty overlay can make that
proof proportional to changes. Compilation must evaluate the requested semantic closure, but it
does not need one disposable program per four entrypoints or unrelated owners. Exact verify output
has irreducible information size, but repeated transitive payload embedding and one giant in-memory
transaction are not required.

## Alternatives

- Raise memory and timeout limits. Rejected because it conceals repeated representation and work.
- Memoize only the final terminal transcript. Retained as C0 projection optimization, not accepted
  as C1, C2, C3, or verify qualification.
- Trust modification times or caller changed paths. Rejected as semantic authority; retained only as
  candidate narrowing with complete fallback.
- Implement Git trees or index semantics in Codegraph. Rejected. The installed Git executable is
  the adapter authority and keeps the boundary auditable.
- Adopt `libgit2` or another Git implementation initially. Deferred because it adds native
  distribution and a second semantics surface without improving the proof contract.
- Rewrite the compiler or analysis engine in Rust. Deferred until removal of repeated work exposes a
  measured CPU-bound leaf that justifies it.
- Preserve embedded module declaration closures and increase the protocol ceiling. Rejected because
  it makes memory scale with repeated transitive ownership rather than unique semantic evidence.

## Compatibility, migration, and gate effects

All current commands and diagnostics remain available. Application identities intentionally change
when their requested capability set changes. Existing checkpoints and analysis generations are
regenerable; incompatible versions miss rather than migrate in place. Semantic packs add no daemon
or repository-executed extension and are read-only inputs to ordinary checks.

The canonical complete compiler remains installed and qualified throughout the migration. Each
optimization can be disabled independently for differential qualification and recovery. No node may
claim graduation from a replay, a pre-primed cache, a relaxed limit, omitted diagnostics, a narrowed
hidden corpus, or a candidate-authored baseline.

## Objections and dispositions

- Objection: removing statistics from ordinary checks weakens the application snapshot. Disposition:
  statistics remain an exact capability for viewer and reporting consumers; ordinary check identity
  explicitly declares a smaller capability plan instead of silently dropping data.
- Objection: Git cannot represent meaningful empty directories. Disposition: Codegraph rejects
  empty normative directories today. If another admitted empty directory affects semantics, the
  SourceProof adds a small scope topology overlay or visibly uses the complete scanner.
- Objection: advisory publication cannot both preserve output and report failure. Disposition: cache
  failure is a structured lifecycle receipt and telemetry event, included in qualification and debug
  evidence but excluded from canonical check diagnostics and exit status.
- Objection: file-count and LOC gates can reward fragmentation. Disposition: the gate is a ratchet
  plus ownership/import review; it rejects empty facades and measures largest-file distribution,
  cycles, and semantic cohesion rather than minimizing one number.
- Objection: C3 below three seconds may be impossible. Disposition: no current measurement proves
  that. It remains separate from the already achievable C1 product target, and failure must expose
  causal lower-bound evidence rather than silently redefining cold.

## Consensus and decision

Accepted by the maintainer through the explicit 2026-08-22 direction to pursue state-of-the-art cold
and warm performance while preserving capabilities, correctness, maintainability, observability,
and anti-gamed qualification. The accepted oracle prohibits semantic shortcuts. Implementation is
split into bounded independently reversible nodes so evidence can redirect the critical path without
weakening the final target.
