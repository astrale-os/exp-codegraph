# V2-REV-024: Cut application authority through one inventory-pinned Codegraph spine

Status: accepted

Date: 2026-08-15

Affected requirements: V2-APP-001, V2-APP-002, V2-APP-003, V2-CON-004, V2-MIG-002, V2-MIG-004, V2-MIG-005, V2-MIG-006, V2-MIG-007, V2-QLF-005, V2-QLF-007, V2-QLF-010

Review perspectives: Codegraph product, application and analysis lifecycle, consumer and DX, specification governance, qualification and performance

## Existing decision

Gate 5 required one coordinated switch from the historical TypeSpec application authority to the
V2 application service. The first service implementation composed the correct immutable products,
but every refresh recompiled and qualified the complete corpus. The frozen application limits were
also inherited from a 150-specification baseline, while the authoritative Kernel-only spine now
contains 306 specifications. V2-MIG-006 prohibited every compatibility alias without distinguishing
a semantic fallback from the temporary source spelling needed during the TypeSpec-to-Codegraph
package rename.

## Decision

- The headless application service is the sole workflow authority for CLI, CI, server, watcher,
  source operations, qualification transport, catalog projection, and viewer inputs.
- A no-change refresh recomputes the local repository inventory and returns the retained immutable
  snapshot only when its inventory and normalized semantic request are identical. Explicit changes,
  invalidation, and external schema roots bypass this fast path.
- Different selections over one inventory share a one-entry immutable compiled corpus, source
  service, and statistics report. This is an application-local reuse mechanism, not a second store
  or semantic authority.
- Whole-corpus qualification opens each pinned universe/capability view once and qualifies the
  corpus as a batch. Individual qualification remains a wrapper over that same operation.
- Application identity hashes exact component identities and compact corpus digests rather than
  serializing a repository-sized nested snapshot as its hash preimage.
- Cold full-application duration is recorded against a 300,000 ms diagnostic reference, not used as
  a Gate 5 pass predicate. Exact unchanged runs varied from 185,478.13 to 381,897.14 ms, while the
  isolated causal cold comparison already qualified the affected-shard candidate as 27.63 percent
  faster. Warm, focused, affected-edit, native-startup, SQLite-size, and the 3,584 MiB whole-process
  RSS ceiling remain hard predicates. The existing memory-limit name remains stable for this cut,
  but qualification measures whole-process RSS rather than claiming it is V8 heap usage.
- V2-MIG-006 continues to prohibit legacy semantic authorities, archive adapters, runtime modes,
  converters, and forwarding exports. During the incremental package rename only,
  `@astrale-os/spec/authoring` may be recognized as inert authoring source syntax equivalent to
  `@astrale-os/codegraph/authoring`. It is not exported, executed, selected by a flag, or used as a
  fallback reader; new Codegraph sources and generated examples use the canonical spelling.
- Only Kernel-owned `.spec` modules are authoritative. Removed product Domain specifications are
  neither rediscovered nor represented as accepted parity drift.

## Evidence and motivation

The installed Kernel holdout contains 306 authoritative specifications. Batch qualification proves
that pinned analysis queries are opened per universe rather than per specification. Focused tests
prove an identical request performs only inventory work and that a different selection reuses the
same compiled corpus; a changed source produces a new inventory and snapshot.

Two exact full-application runs peaked at 3,088.98 and 3,145.47 MiB RSS. Phase attribution on the
latter was 3,145.47 MiB during cold, unchanged during warm, and unchanged during focused selection;
current RSS moved only from 2,624.95 to 2,651.19 MiB across those phases. The peak is therefore not
caused by retaining duplicate focused snapshots. It is the measured cost of the doubled normative
corpus and its full application qualification. Raising the stale 2,048 MiB ceiling to 3,584 MiB
preserves a finite measured guardrail without inventing another benchmark matrix or blocking the
authority cut on a representation redesign.

The warm application failure was causal, not statistical: unchanged refresh previously took
48,508.03 ms because it recompiled and requalified 306 specifications. The inventory-pinned fast
path makes those phases exactly zero while still checking every local byte identity.

Cold full-application runs over identical semantics ranged from 185,478.13 through 248,625.21 and
253,689.65 to 381,897.14 ms. Absolute limits inferred from the earlier samples therefore classified
ordinary run-to-run variation as an architectural failure. The reference remains visible in every
artifact, while causal phase counters and the much tighter warm/focused/affected ceilings govern
architecture. The 381,897.14 ms run remains explicitly diagnostic-only because it ran before this
revision's final disposition; it is not rewritten into qualified evidence.

## Alternatives

- Keep repeating whole-repository samples or raise a pass ceiling after every outlier. Rejected: the
  affected-shard experiment already established that long historical matrices are noisy and poor
  causal evidence. Cold is recorded, and isolated causal comparison governs regression instead.
- Redesign `SpecificationSnapshot` into a normalized graph before Gate 5. Deferred: it may reduce
  cold memory, but it changes a broad normative model after semantic qualification and is not needed
  for correct application authority.
- Persist a general application cache. Rejected: one inventory-keyed in-process corpus removes the
  duplicate work without introducing invalidation, migration, or cache-authority problems.
- Drop the old authoring package spelling immediately. Rejected for this cut because the pinned
  Kernel consumer has not yet completed the mechanical package rename; recognizing the inert syntax
  does not retain a V1 semantic implementation.

## Compatibility, migration, and gate effects

Gate 5 may qualify after one final Kernel application proof, focused consumer tests, full package
tests/typecheck/specification checks, and negative scans for deleted V1 authorities. Gate 6 still
owns release installation, self-hosting, SDK-like extension, and the final source-spelling removal
when downstream Kernel authoring has migrated.

Rollback remains source-control revert plus deletion of regenerable cache files. There is no live
dual-write, legacy runtime switch, or alternate reader.

## Objections and dispositions

- Objection: a 3,584 MiB ceiling is too high for an editor tool. Disposition: it is a whole-process
  full-corpus qualification ceiling, not the target for normal catalog or focused work. Demand-driven
  native projection, affected-shard refresh, header-first queries, and the warm fast path already
  keep ordinary operations proportional. A normalized normative corpus requires its own measured
  proposal rather than being smuggled into Gate 5.
- Objection: any old package spelling violates the clean cut. Disposition: the exception is parser-
  only input syntax with one canonical semantic helper identity. It grants no executable or
  authoritative compatibility path and is explicitly temporary through Gate 6.

## Consensus and decision

Accepted by the maintainer under the explicit direction to preserve causal evidence, stop the noisy
matrix, avoid over-engineering, and move through the critical path. The decision keeps the semantic
and authority cut strict while allowing the package name to migrate incrementally.
