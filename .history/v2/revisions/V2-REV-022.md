# V2-REV-022: Make demand-driven body semantics independent of checker display order

Status: accepted

Date: 2026-08-15

Affected requirements: V2-ANA-012, V2-TS-008

Review perspectives: TypeScript semantics, native projection, portable identity, performance, qualification governance

## Existing decision

Requested native capabilities select independent projectors, and every selected namespace must equal
the corresponding namespace from an all-capability cold build. The microproject passed, while the
real Codegraph and Kernel corpus qualification was still pending.

Resolved body calls stored `TypeChecker.SignatureToStringEx` output as their signature. That display
API may choose an authored alias, expanded type, imported name, or truncation marker based on
unrelated prior checker walks.

## Proposed decision

- Resolved call signatures remain human-readable strings, but are composed from parameter names,
  optional/rest shape, and ttsc's stable fully-qualified rendering of every parameter and return
  type.
- Unrelated symbol discovery cannot influence body payloads, fact identities, or generations.
- The native semantic pass version advances from 1.0.0 to 1.1.0 because body fact content changes.
- Module-only and body-only projections must be byte-semantically identical to their namespace in a
  rich cold build on the microproject, Codegraph, and Kernel.
- Function-scoped body demand remains a future extension. It will be added only with a real SDK rule
  that proves candidate selection, scope completeness, and an end-to-end benefit.

## Evidence and motivation

The first full-corpus differential found three of 3,805 Codegraph body facts whose signatures changed
with projection order. Exact witnesses included `NonNullable<Alias>` versus an expanded readonly
array, `ReadonlyMap<string, Symbol>` versus `ReadonlyMap<...>`, and an authored viewer type versus an
import-qualified type. Module facts were already exact and no unrequested semantic phase executed.

The corrected generated evidence proves:

| Corpus | Rich cold | Module-only | Ratio | Body-only | Ratio | Exact selected facts |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Codegraph | 90,875.84 ms | 1,717.12 ms | 52.92x | 69,506.50 ms | 1.31x | yes |
| Kernel core | 22,614.79 ms | 8,379.87 ms | 2.70x | 11,583.78 ms | 1.95x | yes |

Every run retains the same project universe and source manifest across projection plans. Module-only
executes only module projection; body-only executes only body projection. The focused alias fixture
and both real corpora reconstruct exact selected fact envelopes.

## Alternatives

- Always run complete symbol discovery before body projection. Rejected because it would hide an
  ordering bug by reintroducing repository-wide work into a body-only plan.
- Delete resolved signature text. Rejected because it is valuable portable call evidence and the
  checker exposes enough stable type machinery to retain it.
- Freeze `SignatureToStringEx` output with string rewrites. Rejected because aliases and truncation
  represent semantic structure, not path noise that a safe regex can normalize.
- Implement function-scoped native body extraction now. Deferred because namespace demand already
  produces a 53x catalog improvement, while body-only remains dominated by real body work. A stable
  scope/completeness contract should be driven by the SDK extension rather than speculation.

## Compatibility, migration, and gate effects

The public `ResolvedCall.signature?: string` shape and body schema version remain unchanged. The
string becomes deterministic and may differ from pre-1.1 diagnostic formatting, so body fact IDs,
shard digests, and generation IDs correctly change under pass version 1.1.0. Consumers must not parse
the display string as an authority; target symbols and parameter bindings remain the semantic join.

V2-ANA-012 is qualified by `.history/v2/evidence/demand-driven-projection.json`. No new `.spec`
physical inventory is added: the governed demand law and body API remain the durable boundary, while
the corpus differential harness is volatile qualification machinery.

## Objections and dispositions

- Alias-fidelity objection: fully qualified rendering can prefer a canonical type over the authored
  alias. Accepted for resolved call display; authored public type facts remain the lossless alias
  authority.
- Performance objection: body-only is only 1.31x faster on Codegraph. Accepted as evidence that body
  traversal is the real cost and that another storage or protocol redesign is not an easy win.
- Versioning objection: changing output under pass 1.0.0 would be invisible. Resolved by the 1.1.0
  pass version before governed evidence was generated.

## Consensus and decision

Accepted. Demand-driven namespace projection is exact and qualified on Codegraph and Kernel. The
ordering defect is fixed generically, while deeper candidate scoping remains an explicit measured
extension rather than a premature engine redesign.
