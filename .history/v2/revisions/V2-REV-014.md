# V2-REV-014: Retire the executable V1 oracle at the coordinated authority cut

Status: accepted

Date: 2026-08-15

Affected requirements: V2-TS-016, V2-TS-017, V2-TS-018, V2-TS-019, V2-TS-020, V2-TS-021, V2-TS-022, V2-SPC-002, V2-MIG-003, V2-MIG-005, V2-MIG-006, V2-QLF-001, V2-QLF-010, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 0 froze V1 observations before V2 implementation. Gates 3 and 4 used executable capture,
projection, comparison, and drift-policy code to prevent unexplained changes while V1 remained the
operational authority. The ledger retained those implementation paths after the coordinated
authority cut, even though the cut requires V1 readers and compatibility machinery to disappear.

## Proposed decision

The immutable, content-addressed Gate 0 through Gate 4 evidence remains historical qualification
input. Its capture and V1-specific comparison implementations do not remain production or
qualification authorities after the cut. Reusable safeguards are retained as generic operations:
project historical evidence onto an explicit current authority set, group differences by stable
fingerprint, and fail closed unless each fingerprint is accepted.

Semantic TypeScript corrections continue to be proven by their exact ttsc fixtures, native
qualification, laws, and regression tests. Historical JSON and review records remain witnesses to
the already completed gates; they are not regenerated, imported by ordinary application paths, or
used to force the new system to reproduce a retired defect.

## Evidence and motivation

The coordinated deletion removed all active manifest readers, V1 catalog and verifier authorities,
oracle capture scripts, parity comparators, and compatibility transports. All in-repository
consumers now use immutable specification, analysis, qualification, application, and presentation
boundaries. The full package typecheck and 340-test suite pass after the cut, while the permanent
repository scan reports no obsolete specification anchors.

The first governance run after deletion correctly reported every stale traceability locator. The
ledger is therefore rebound to existing semantic tests and preserved evidence rather than to
placeholder files or hand-edited generated evidence.

## Alternatives

- Keep the executable V1 oracle indefinitely. Rejected because it preserves a second semantic
  authority and makes complete legacy deletion impossible.
- Delete all historical evidence. Rejected because it would erase the witnesses and accepted drift
  decisions that justified the migration.
- Mark all prior drift irrelevant. Rejected because those decisions explain why V2 deliberately
  differs and remain valuable regression context.
- Add compatibility forwarding files at the deleted paths. Rejected because path-shaped aliases
  would conceal dead authority and violate the clean-cut requirement.

## Compatibility, migration, and gate effects

Gates 0 through 4 retain their completed evidence and decisions. No public V2 fact, store,
specification, conformance, application, or presentation contract changes. Gate 5 may qualify the
coordinated consumer and authority cut only after current consumers, package installation, and
operational limits pass. Gate 6 still requires self-analysis, native release packaging,
performance evidence, and zero active V1 symbols.

Historical evidence readers are diagnostic-only and accept explicit authority inputs. Ordinary
application refresh, CLI, server, watcher, and viewer paths cannot invoke a V1 capture or
comparison implementation.

## Objections and dispositions

- Product objection: removing the executable oracle may hide future regressions. Resolved because
  future regressions are judged against ratified V2 contracts, exact cold/incremental equality, and
  current semantic fixtures; the historical oracle was never normative.
- Analysis/native objection: historical compiler differences may be forgotten. Resolved by
  retaining immutable evidence, accepted revisions, drift witnesses, ttsc qualification fixtures,
  and native semantic laws.
- Consumer/DX objection: old commands can no longer reproduce V1. Accepted as the intended result
  of the authority cut; released consumers receive only the codegraph application and headless
  modules.
- Qualification objection: deleting verification code could make completed rows unverifiable.
  Resolved by traceability to immutable evidence plus current generic fail-closed projection and
  semantic regression tests. No generated evidence is rewritten.

## Consensus and decision

Accepted under the user's explicit authorization to perform the coordinated V1 deletion, preserve
genuinely valuable generic machinery, avoid overfitting V2 to the oracle, and require tracked,
justified differences. All four perspectives agree that retaining immutable witnesses while
deleting executable V1 authority is the sound post-cut boundary.
