# V2-REV-004: Treat complete public closure and qualified compiler diagnostics as authority

Status: accepted

Date: 2026-08-14

Affected requirements: V2-TS-001, V2-TS-014, V2-TS-016, V2-CON-001, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 4 preserves consumer-significant dependency topology and diagnostic behavior unless an
accepted semantic correction explains a V1 defect. The first comparator treated every V1 logical
dependency set and every V1 compiler diagnostic as equality authorities.

Admin corpus evidence disproved both assumptions. V1 omitted eleven platform `Promise` API edges
and one workspace `LocalBinding` API edge even though each target declaration is issue-free and
checker-reachable from an exported declaration. V1 also retained three Node TypeScript TS7022 and
TS7024 diagnostics caused by its circular-inference limitation in a delayed repository-factory
closure; the qualified TypeScript-Go project resolves that closure without diagnostics.

## Proposed decision

- The complete checker-resolved declaration closure of every exported declaration is authoritative
  for public API ownership. A reachable external declaration produces an API dependency even when
  V1 traversal omitted it.
- Gate 4 accepts an additional V2 API relationship only when its occurrences name declarations in
  the same module fact, those declarations have no observation issues, and graph traversal from the
  module exports reaches every named declaration. Every accepted relationship is enumerated.
- V1 dependency relationships remain a required subset. Missing V1 relationships and additional
  runtime, type, side-effect, dynamic, or unreachable API relationships still fail.
- TypeScript-Go is the ratified V2 diagnostic authority. The three frozen Admin diagnostics are
  accepted only at their exact module, source, code, line, and column. Any other diagnostic change
  remains unexplained drift.
- Compiler diagnostics and semantic surface facts remain separate. V2 does not synthesize an old
  compiler diagnostic to make an oracle byte-equal.

## Evidence and motivation

The additional `Promise` relationships originate at exported async functions whose normalized
return type references `platform:typescript#Promise`. The `LocalBinding` relationship originates at
the exported `OperationRepository` surface through `MutationInputOperation`; its declaration is
owned by `core/graph/graph`. These are public owners, not implementation imports.

The Admin diagnostic difference is limited to `admin/backend/control-plane/repository.ts` at the
known mutually wired `OperationRepository` and `InstanceRepository` construction. The public
factory return is explicitly `AdminRepositoryFactory`, the closure is not invoked during
construction, the TypeScript-Go project reports no compiler issue, and cold and incremental native
analysis converge on identical diagnostic-free facts.

## Alternatives

- Drop the extra public owners to match V1. Rejected because downstream impact and package-boundary
  queries would be knowingly incomplete.
- Accept every V2 dependency superset. Rejected because implementation imports or an over-expanded
  closure could then bypass parity without semantic proof.
- Re-emit TS7022 and TS7024 from V2. Rejected because a historical compiler limitation is not a
  TypeSpec rule and a second diagnostic implementation would violate compiler authority.
- Edit Kernel production code solely to silence the frozen oracle. Rejected at this gate because it
  would mutate the Gate 0 input to accommodate migration tooling; an independently useful source
  refactor may still be made later under its own review.

## Compatibility, migration, and gate effects

The V2 dependency graph becomes a strict, evidence-proven semantic superset at the twelve observed
Admin relationships. Consumers gain more complete impact information. No V1 relationship is
removed. Presentation may group platform dependencies, but stored facts retain exact target and
declaration provenance.

At Gate 5, the three obsolete Node compiler diagnostics disappear with the compiler authority
switch. The drift report is the migration record. Gate 4 remains fail-closed because both
exceptions use narrow predicates and all observations are materialized in qualification evidence.

## Objections and dispositions

- Product objection: additional edges may make dependency reports noisier. Accepted; truthful API
  ownership is primary, while presentation can group platform providers without deleting facts.
- Analysis/native objection: closure reachability could accidentally traverse implementation
  declarations. Resolved by starting only at exported declarations and requiring the declaration
  identities emitted by the same canonical surface closure.
- Consumer/DX objection: platform declarations can move between TypeScript library files. Resolved
  at identity level by provider-qualified symbols; exact file location remains provenance and is
  intentionally requalified on compiler upgrades.
- Qualification objection: accepting missing diagnostics can hide an analyzer regression. Resolved
  by matching the exact frozen three diagnostics and retaining independent TypeScript-Go project,
  cold-build, incremental, and zero-diagnostic checks.

## Consensus and decision

Accepted under the TypeSpec owner's direction to track and justify genuine oracle flaws rather than
design V2 around them. The correction strengthens the headless semantic graph, remains above the
ttsc Checker instead of duplicating it, and keeps all unknown differences failing.
