# V2-REV-023: Prefer independently addressable payloads for interactive queries

Status: accepted

Date: 2026-08-15

Affected requirements: V2-ANA-013, V2-STO-001, V2-STO-007, V2-QLF-006

Review perspectives: query complexity, SQLite materialization, semantic transparency, application DX, qualification scope

## Existing decision

SQLite supported per-fact inline JSON and one Brotli-compressed payload array per immutable shard.
The compressed layout had become the default before the store-wide experiment was qualified.
Compact TypeScript bodies were also available through an explicitly negotiated physical codec.

## Decision

- `inline-json` is the default SQLite payload materialization because it independently addresses
  selected payloads.
- `shard-brotli` remains an explicit bounded option for archival or predominantly full-scan
  consumers; it is not advertised as the interactive production default.
- The ordinary application does not negotiate compact TypeScript bodies. The generic codec seam
  and the explicit TypeScript codec remain available to specialized consumers and experiments.
- Neither failed experiment is promoted by revising its frozen thresholds. The completed samples
  remain diagnostic evidence and the historical baseline is not a permanent runtime dependency.
- A bounded compressed-block layout or direct compact native builder requires a new measured
  experiment, not an implicit extension of EXP-002 or EXP-003.

## Evidence and motivation

The six-pair Codegraph factorial proved that compact bodies reduced physical body bytes 5.453 times
and wire bytes 2.098 times, but reduced process-tree RSS only 1.219 to 1.471 times and did not establish
cold no-regression confidence. It therefore failed its frozen production gates.

Generic shard compression reduced Codegraph SQLite size 1.907 times with semantic bodies. A short
same-revision Kernel trial confirmed a 1.937-times size reduction and exact semantic identity, with
nearly neutral cold analysis. It also exposed the architectural cost hidden by the Codegraph sample:
point hydration was 4.00 times slower, a first hydrated page 7.67 times slower, evaluator indexing
3.38 times slower, and full typed export 11.77 percent slower. One payload lookup was decompressing
and reconstructing its entire owning shard.

The simplest sound correction is a default selection, not another storage redesign. Header-first
queries already avoid payload work; inline materialization now preserves that proportionality when
the selected identities are hydrated.

## Alternatives

- Keep shard Brotli as the default for its database reduction. Rejected because normal point, page,
  and policy inputs would pay repository-unrelated reconstruction work.
- Delete shard compression. Rejected because it is bounded, semantically transparent, and useful
  for explicit archival/full-scan workloads.
- Delete the compact-body codec. Deferred because the generic seam is sound and the transport
  reduction can matter to constrained specialized consumers, but it receives no ordinary product
  adoption.
- Implement bounded compressed blocks immediately. Rejected as a new schema, migration, cache, and
  query design without a current consumer requiring both sides of the tradeoff.

## Gate effects

The durable SQLite law now states the selective-hydration default. Focused tests pin the exported
default and actual stored layout while existing equivalence, corruption, migration, cache-bound,
and explicit compressed-layout tests remain authoritative. This decision adds no new `.spec` file
inventory for private compression mechanics.

## Consensus

Accepted. Codegraph keeps the useful mechanisms but makes the low-complexity query path the default.
The experiments are closed honestly and work returns to the Gate 5 application cutover.
