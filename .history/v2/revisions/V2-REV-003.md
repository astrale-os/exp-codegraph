# V2-REV-003: Qualify stable semantic contracts instead of V1 compiler serialization

Status: accepted

Date: 2026-08-14

Affected requirements: V2-ARC-002, V2-ANA-004, V2-TS-004, V2-TS-011, V2-TS-015, V2-CON-001, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 4 compares V1 and V2 at normalized declaration and diagnostic levels, and unexplained drift
fails. The first comparator interpreted this as exact equality of the complete V1 declaration wire
shape except for individually patched fields. That made V1 compiler serialization an accidental
second specification: byte offsets in platform identities, checker-reduced boolean unions,
distributed intersections, and flattened alias boundaries all constrained the V2 representation.

The legacy `typescript/model.ts` was also temporarily redirected to the V2 surface model. This
allowed frozen V1 verification code to constrain new generic TypeScript facts whenever the V2
vocabulary gained a soundly representable TypeScript construct.

## Proposed decision

V1 remains a reproducible compatibility witness, not a structural schema for V2.

- Consumer-significant module ownership, export coverage, dependency topology, package intent,
  source coverage, error extraction, diagnostic behavior, and completion remain exact unless a
  separately accepted semantic drift record says otherwise.
- V2 public type surfaces preserve explicitly authored aliases and algebraic structure while using
  TypeScript-Go Checker resolution for canonical targets, substitutions, signatures, and types not
  recoverable from public syntax.
- Platform symbol identities use a position-independent provider and qualified symbol path.
- A checker-reduced or assignability view, when a downstream capability needs one, is a separate
  derived fact produced from the resident ttsc project. It never replaces source-semantic facts and
  never creates a second compiler lifecycle.
- Representation differences are accepted only by a named, fail-closed equivalence class with an
  adversarial fixture. Exported declaration coverage and shared identity/kind remain exact;
  non-exported, issue-free closure additions or removals are enumerated as drift, and unknown shape
  differences remain failures.
- The V1 observation model stays frozen and isolated until deletion. V2 surface contracts may
  represent additional TypeScript constructs without widening the V1 evaluator.

## Evidence and motivation

Admin corpus comparison found semantically identical declarations serialized differently solely
because Node TypeScript and TypeScript-Go expose different internal reductions. Examples include
`boolean` versus `false | true`, `A & (B | C)` versus `(A & B) | (A & C)`, and an explicit alias
reference versus its expanded checker type. The same comparison found the logical `Date` symbol
embedding different standard-library byte offsets in the two compiler revisions.

Trying to reproduce these details increased native code and qualification time without protecting a
consumer contract. It also hid a real V2 capability gap: the V1 closure happened to flatten away an
authored `object` keyword, so an exact-oracle implementation did not model `object`, `bigint`,
`symbol`, or lossless bigint literals. The revised adversarial native fixture owns those V2
requirements directly, including private-member exclusion and stable platform identity.

## Alternatives

- Continue exact V1 wire parity with more exceptions. Rejected because exceptions would grow with
  compiler upgrades and make V1's incidental representation normative.
- Drop V1 comparison entirely. Rejected because ownership, coverage, dependency, diagnostic, and
  consumer regressions still need an independent migration witness.
- Run Node TypeScript beside ttsc to retain V1 shapes. Rejected because two semantic compiler
  lifecycles violate the ratified substrate and incremental-authority decisions.
- Store only checker-reduced types. Rejected because reduction discards authored alias and
  algebraic provenance that policy and indexing consumers need.

## Compatibility, migration, and gate effects

Gate 4 becomes contract parity rather than serialization parity. Its report separates exact
invariants, accepted equivalence classes, accepted semantic corrections, capability gaps, and
unexplained failures. The full V1 wire remains inspectable for audit and drift discovery.

The pre-authoritative V2 type surface adds faithful intrinsic primitive and bigint-literal variants.
No V1 application sees that shape before Gate 5. Existing V1 consumers continue compiling against
the isolated frozen model and disappear in the coordinated cut rather than receiving adapters.

This revision does not weaken compiler or diagnostic coverage. Missing ttsc evidence is unavailable
or failing until qualified; it cannot be normalized into success. Application cutover remains
blocked until consumer-visible diagnostic differences have an explicit disposition.

## Objections and dispositions

- Product objection: semantic equivalence could hide a missing member. Resolved by making accepted
  equivalence classes narrow and fixture-backed; ownership, declaration/export coverage, and
  unexplained structural differences still fail.
- Analysis/native objection: preserving syntax could duplicate checker data. Resolved by one
  source-semantic base fact plus optional derived capabilities, not two authoritative fields in
  every fact.
- Consumer/DX objection: aliases may require expansion for simple queries. Resolved by a bounded
  derived expansion/query capability over canonical identities; the base fact remains attributable.
- Qualification objection: V1 no longer supplies every expected byte. Resolved by retaining exact
  comparison for stable invariants and reporting every accepted representation class and semantic
  revision separately.

## Consensus and decision

Accepted following the TypeSpec owner's explicit direction not to overfit oracle defects and to
remove V1-driven over-engineering while preserving genuinely useful compatibility evidence. The
decision strengthens the headless ttsc-wrapper boundary: ttsc remains semantic authority, native
code only extracts portable evidence, and reusable derivation stays above it.
