# V2-REV-009: Reconcile conformance without reproducing V1 blind spots

Status: accepted

Date: 2026-08-14

Affected requirements: V2-TS-014, V2-TS-015, V2-TS-016, V2-TS-022, V2-CON-001, V2-CON-002, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 4 compares qualification produced from immutable V2 specification and analysis snapshots with
the frozen V1 oracle. The oracle is observational rather than normative: every difference must be
explained, but a V1 analyzer defect or missing observation must not be reproduced merely to improve
parity. V2 separately reports authored-obligation and observed-evidence coverage, retains exact
compiler provenance, and treats unavailable evidence as indeterminate.

The first full qualification comparison had two problems. Its oracle join treated the 275 V1
verification rows as if they were the complete catalog, even though the frozen V1 catalog contains
309 specifications. It therefore described 34 nested Shell specifications as new V2 modules rather
than specifications whose V1 verification was suppressed. It also exposed several V2 comparison
defects around callable aliases, optional authored aliases, asserted concise-arrow returns, and
causal dependency bookkeeping. Those defects created cascaded identity and stale-import findings
that were not present in V1 and were not accepted as drift.

## Proposed decision

- Oracle comparison joins catalog presence and qualification evidence separately. A module is new
  or removed only when the frozen catalog and current authored corpus differ. A catalogued module
  without a V1 verification row is reported as newly observable evidence, including its complete V2
  status, per-profile diagnostics, and bidirectional coverage.
- One project-level blocker never erases other authored specifications. V2 proves target presence
  per module and preserves compiler or completeness issues in the affected semantic profiles. It
  does not translate a causal project problem into pass, and it does not fabricate surface mismatch
  rules when no module observation exists.
- A callable alias is compared by its invoked signature, not by treating the whole alias value as
  its return. Optional authored parameter aliases remain exact when no generic substitution occurs,
  and a concise-arrow terminal type assertion is exact return evidence.
- Missing callable slots mark their authored type dependencies causally used, and named reference
  evidence inside an algebraic type remains attributable even when another constituent fails. A
  missing parameter can therefore remain a real finding without producing a second false stale
  import finding.
- Coverage is a V2 metric, not a V1 count-preservation exercise. Forward totals contain actual
  authored obligations evaluated by the profile; inverse totals contain normalized observed facts.
  Blocked downstream profiles report zero evaluated obligations, target existence is one forward
  structure obligation, and complete dependency closure is counted from portable logical facts.
- The accepted comparison is content-addressed by class. Zero newly detected findings applies only
  to the 275 directly comparable V1 qualification records. The 34 previously suppressed Shell
  records remain a separate, fully pinned class and their failures remain visible.

## Evidence and motivation

Fresh ttsc 0.26.2 / TypeScript-Go 7.0.2 extraction produced 303 complete module facts across 15
compiler universes for all 309 authored specifications. Six specification-only authentication
leaves remain explicitly unobserved. Memory and normalized SQLite materialization exported
identical manifests, capabilities, facts, and qualification inputs for every universe.

The corrected V1 join proves exact catalog equality: 309 specifications on both sides, no V1-only
or V2-only module, and 275 directly comparable qualification records. V1 assigned one
`WORKSPACE_DEPENDENCIES_UNAVAILABLE` blocker to the Shell root and emitted no verification record
for the other 34 catalogued Shell specifications. V2 qualifies all 34: 21 pass and 13 error. The 13
errors retain the exact underlying TypeScript and completeness diagnostics, including 40 TS2307
occurrences, rather than disappearing behind the V1 blocker.

After the callable and dependency fixes, the complete comparison contains no newly detected
finding among the 275 comparable records and no unexplained difference. Its 469 raw differences are
partitioned into 34 newly observable Shell records, 368 coverage-model witnesses, 12 causal
unavailable-evidence refinements, 43 V1 findings corrected by this and prior accepted revisions,
eight diagnostic refinements that keep the profile failing, and four error-to-fail status
refinements. Every class has an exact count and SHA-256 witness; any membership or payload change
fails closed.

The regression suite proves invoked callable aliases, exact optional aliases, terminal asserted
returns, bounded template-union comparison, missing-slot dependency causality, algebraic reference
evidence, unobserved-module epistemics, focused closure, and changed or unclassified oracle drift.

## Alternatives

- Require the 34 Shell records to remain absent. Rejected because absence is a V1 observability
  defect, not proof that those authored specifications conform.
- Treat every newly observable Shell record as a pass. Rejected because 13 contain real compiler or
  completeness errors which must remain queryable and actionable.
- Compare only V1 and V2 top-level status. Rejected because it would hide changed diagnostic
  meaning, coverage, and missing profile evidence.
- Preserve V1 coverage counts. Rejected because V1 counted blocked obligations and incomplete
  dependency evidence in ways that conflict with the ratified V2 epistemic and closure contracts.
- Silence stale imports whenever any nearby obligation fails. Rejected because only exact causal
  type dependencies may be marked used; unrelated stale imports remain genuine findings.
- Loosen identity comparison until parity passes. Rejected because it would erase the exact alias,
  symbol, and provider guarantees required by downstream indexing and policy consumers.

## Compatibility, migration, and gate effects

This changes only shadow qualification and evidence before Gate 5. Public analysis facts and store
contracts remain versioned and regenerable. Qualification consumers gain a truthful distinction
between catalog presence, evidence availability, mismatch, and analyzer failure. Existing real
Kernel findings remain present; only exact audited V1 false positives and cascades are removed.

Gate 4 may complete only from a fresh native full-corpus run whose checkpoint digest, native digest,
memory/SQLite differential, qualification digest, raw difference digest, class witnesses, and
governance authorities all match. Focused inspection remains advisory and cannot write the governed
witness.

## Objections and dispositions

- Product objection: surfacing 13 Shell errors makes V2 look worse than V1. Rejected; V1 omitted the
  specifications rather than proving them, while V2 keeps the problems attributable and fixable.
- Analysis/native objection: an asserted return can lie. Resolved by treating only the
  compiler-checked terminal assertion of a concise arrow as exact evidence; arbitrary body syntax
  is not elevated to a declaration contract.
- Consumer/DX objection: coverage totals no longer compare numerically with V1. Accepted because
  the directions now have stable definitions and the full raw differential remains available.
- Qualification objection: broad semantic predicates could accept future drift. Resolved by narrow
  classification plus exact content digests, zero unexplained entries, and a fresh-native write
  requirement.
- Maintainability objection: oracle code could become another monolith. Resolved by separating the
  model, comparison, classification, digest, and policy into one hierarchical leaf module.

## Consensus and decision

Accepted before Gate 4 authority evidence is written. The product perspective requires newly
observable failures to remain visible; analysis/native requires exact compiler identities and
causal evidence; consumer/DX requires stable status and coverage meaning; qualification requires a
catalog-complete, content-addressed, fail-closed comparison. No remaining objection demonstrates a
soundness, safety, or consumer-contract violation.
