# V2-REV-026: Close self-hosting by semantic coverage rather than backend multiplication

Status: accepted

Date: 2026-08-16

Affected requirements: V2-QLF-009

Review perspectives: Codegraph product, analysis and persistence, consumer and DX, qualification and performance

## Existing decision

Gate 6 required Codegraph and Kernel self-analysis, suspicious-fact audit, cold and incremental
equality, SQLite reconstruction, and reruns after generic defects were corrected. The first
multi-project harness interpreted this as a complete Cartesian product: every Kernel compiler
universe through memory, SQLite, reopen, and another cold mirror even after the generic store and
incremental invariants had already been established.

That interpretation was not stated by the semantic requirement. It retained repository-sized
graphs unnecessarily, reached the 4 GiB Node heap before SQLite work, and then repeated the same
store implementation over nine additional independent project payloads after the richest Kernel
project had passed.

## Decision

- Every owned Codegraph and Kernel compiler universe is analyzed at the maximal requested semantic
  depth in memory, checked for compiler diagnostics and suspicious facts, and refreshed unchanged.
- Codegraph, as the package self-host, must additionally pass complete memory/SQLite/reopen and
  incremental/cold equality.
- Kernel persistence is represented by its richest measured project through SQLite and reopen,
  combined with the generic crash, corruption, migration, rollback, isolation, and memory/SQLite
  suite and the adversarial affected-shard incremental/cold oracle.
- A repository does not need to replay every independent compiler universe through every already-
  qualified backend merely to multiply samples of the same store contract.
- Any universe that exposes a new diagnostic, suspicious candidate, limit, schema, identity, or
  invalidation class becomes a mandatory focused persistence/cold witness before qualification.

This changes qualification scope, not analysis semantics, completeness, persistence behavior, or
the requirement that findings are fixed or explicitly audited.

## Evidence and motivation

Codegraph completed maximal self-analysis with 35 specifications and 74,160 facts, exact
memory/SQLite/reopen equality, warm generation reuse, and relocated incremental equality against
both cold stores. The audit exposed two portable-identity defects; both were fixed and the relocated
oracle then matched exact universe, source manifest, generation, source, module, body, symbol, and
occurrence facts. No compiler diagnostic or implementation defect was accepted as harmless drift.

Kernel resolved all 306 authoritative specifications into ten compiler universes. Every universe
completed maximal memory analysis and warm reuse. The richest FalkorDB universe completed SQLite
materialization and reopen after the snapshot-set harness stopped retaining unrelated graphs. The
Host universe independently exercised the largest 519,627,239-byte physical transaction and caused
the semantic and physical protocol limits to be separated and forwarded correctly under
V2-REV-025.

The generic SQLite suite already proves both stores against identical transactions, stale bases,
rollback, corruption, migration, crash, retention, and isolation. The affected-shard qualification
proves exact incremental/cold equality for Codegraph and Kernel plus conservative fallbacks for
public shape, imports, ambient scope, create/delete/rename, configuration, and uncertainty. Nine
more Kernel SQLite projections would exercise no new semantic or persistence class.

## Alternatives

- Complete all nine remaining SQLite projects and a final cold mirror. Rejected because it repeats
  qualified backend behavior without increasing semantic, invalidation, or schema coverage and was
  explicitly removed from the critical path by the maintainer.
- Drop Kernel persistence evidence entirely. Rejected because the richest real Kernel universe is
  a necessary operational and representation witness beyond synthetic store tests.
- Accept suspicious candidates without exact witnesses. Rejected; present compiler diagnostics
  remain fix-required and every accepted non-defect candidate still requires its exact fingerprint,
  rationale, and witnesses.
- Weaken incremental equality. Rejected; normalized incremental output must remain exactly equal to
  cold memory and SQLite output for the adversarial and repository witnesses.

## Compatibility, migration, and gate effects

No public API, fact schema, store, identity, capability, or limit changes. Gate 6 may close once the
supported native artifact matrix and packed consumers pass, the final package checks and negative
scans are green, and the requirement ledger points to this representative self-host evidence.

Future analyzer or store changes still rerun their owned generic suites. A new self-host finding or
new maximal project class reopens focused evidence for that class; it does not silently inherit this
decision.

## Objections and dispositions

- Qualification objection: representative persistence could miss a project-specific encoding bug.
  Disposition: every universe is semantically analyzed; the richest payload exercises the physical
  path; schemas and codecs are namespace-based rather than project-based; any distinct namespace,
  limit, or candidate class requires its own witness.
- Performance objection: one repository comparison is not a benchmark distribution. Disposition:
  self-hosting is a correctness and operational-admission proof. Performance claims remain causal
  affected-versus-cold comparisons and governed hard limits, not a noisy sampling matrix.
- Product objection: this could redefine completion around work already done. Disposition: the
  retained scope still covers every authoritative specification and compiler universe, maximal
  semantic depth, the richest persistence workload, both repositories, and all distinct failure
  classes. Only redundant backend multiplication is removed.

## Consensus and decision

Accepted under the maintainer's explicit direction to preserve exact semantic qualification while
stopping repetitive whole-repository phases that do not add coverage. The product, analysis,
consumer, and qualification perspectives agree that semantic classes and generic backend contracts,
not project-count multiplication, are the sound completion boundary.
