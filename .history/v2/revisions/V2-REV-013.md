# V2-REV-013: Make the application and downstream evidence boundaries explicit

Status: accepted

Date: 2026-08-14

Affected requirements: V2-ANA-005, V2-ANA-006, V2-ANA-007, V2-ANA-009, V2-ANA-010, V2-ANA-011, V2-TS-010, V2-TS-023, V2-REP-005, V2-REP-006, V2-APP-001, V2-APP-002, V2-APP-003, V2-APP-004, V2-APP-005, V2-CON-004, V2-SEC-004, V2-QLF-006, V2-QLF-007

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

The ADR separated normative specification, observed analysis, derived qualification, and
presentation. It required atomic multi-universe analysis, a capability-aware pass DAG, complete
repository evidence, a coordinated Gate 5 cut, and a future SDK-like extension. It did not define
the application coordinator precisely enough to migrate stateful consumers, and several qualified
foundation contracts were too weak to make that coordinator sound:

- `AnalysisSnapshotSet` prose named repository inventory, but the traceability decision and early
  API originally pinned only universe generations;
- capability completeness was correct only when a capability happened to equal its output
  namespace;
- portable passes declared invalidation inputs but unchanged passes were still reloaded and run;
- policies treated any globally partial body capability as unusable, even when a rule could prove a
  narrower complete evidence slice;
- generic queries forced downstream TypeScript consumers to cast `Fact<unknown>` payloads;
- the application had no complete contract for generation leases, selection closure, observations,
  source transports, or repository statistics; and
- Gate 5 performance limits had no owned application specification or workloads.

Those gaps were found before authority switch. They are not accepted implementation quirks.

## Proposed decision

- `TypeSpecApplicationSnapshot` is an immutable workflow composition above the four authorities,
  not a fifth semantic authority. It names the exact repository inventory, normative snapshots,
  analysis snapshot set, repository statistics, qualifications, and selection authority.
- The application service retains a bounded number of generations. `open(snapshot)` leases the
  exact analysis generations and source inventory until disposal. Absolute roots and timings never
  participate in portable identities.
- Full selection remains authoritative. Focused selection is advisory and records requested,
  primary, selected, support, included, and optional dependent closure explicitly.
- Layout, resolved tests, schema dependencies, and module presentation context are analysis or
  application observation facts, never fields smuggled back into `SpecificationSnapshot`.
- Edit, reveal, and on-demand qualification operations require an admitted application generation
  and source revision. Presentation DTOs consume pinned readers and do not own a store or compiler.
- `AnalysisSnapshotSet` includes the exact inventory revision in its public model, memory and SQLite
  identity, and construction API.
- Capability completeness is derived from the declared output shards that provide it. Capability
  names and namespace names may differ without losing partial or unavailable status.
- Unchanged portable passes carry validated shards without exporting upstream facts, invoking the
  pass, or rewriting immutable rows. Declared namespace inputs, invalidation selectors, output
  schema, mandatory refresh, and upstream capability invalidation are the only generic rerun causes.
- A policy may declare a scoped capability. Every scoped rule reports selected evidence
  completeness; partial or unavailable selected evidence can only yield indeterminate. Returning
  pass or fail from incomplete selected evidence is a policy contract error.
- The TypeScript adapter owns a validating typed reader for project, diagnostic, source, symbol,
  occurrence, body, and module facts. The generic store remains language-neutral and continues to
  expose `Fact<unknown>`.
- Repository statistics are a reusable, headless projection over immutable inventory and
  byte-verified source reads. They retain per-file facts plus orthogonal summaries and a generic
  deepest-root ownership grouping. Binary files remain in byte/file totals and unknown text remains
  unclassified.
- Value evaluation publishes its governed default budget and returns the exact effective limits
  with every evaluated result.
- Gate 5 owns explicit cold, warm, focused, native-startup, SQLite-size, and heap limits plus stable
  workloads. Constants alone do not qualify the gate; measured evidence is still required.

## Evidence and motivation

The Gate 5 consumer inventory showed that a direct CLI/server cut to the first V2 APIs would have
lost layout, attached-test, schema, source, and generation-lifetime guarantees. A separate Gate 6
audit found the capability/namespace completeness defect, full portable-pass recomputation, unsafe
body-fact casts, and the global-partial policy dead end. Regression tests now exercise a capability
whose name differs from its output namespace, a no-change portable carry, a relevant and unrelated
native shard change, a scoped complete rule beside unrelated partial body evidence, and rejection
of a pass result from partial selected evidence.

The application tests exercise portable application identities, inventory-pinned multi-project
snapshot sets, retained readers, focused closure, schema and observation facts, and stale pinned
interactions. The TypeScript fact reader admits valid body payloads and rejects malformed payloads
before consumer access. The value evaluator reports defaults of depth 12, 2,000 steps, and 32
alternatives as effective configuration.

The repository statistics self-host diagnostic retained 4,710 Kernel-worktree files and completed
with zero unreadable or stale sources after binary admission and a governed 16 MiB source-read
bound. It exposed the large historical evidence file rather than excluding it, retained binary
files without line claims, removed false package ownership under `.spec/packages`, and projected
nested TypeSpec modules through the generic deepest-root adapter. This run is diagnostic evidence;
Gate 6 still owns the governed self-host artifact and manual suspicious-fact disposition.

## Alternatives

- Let each CLI, server, and viewer adapter assemble current specification and analysis state.
  Rejected because independent current reads can mix inventories and generations and recreate
  mutable catalog authority.
- Add repository inventory only to the application snapshot. Rejected because a reusable
  `AnalysisSnapshotSet` could still mix its pinned generations with an unrelated inventory.
- Require capability names to equal output namespaces. Rejected because capabilities are semantic
  contracts and one pass may provide a capability through several namespaced schemas.
- Recompute every portable pass and rely on SQLite content addressing to suppress writes. Rejected
  because it still reloads and executes unaffected analysis and violates the incremental contract.
- Ignore global partial completeness for SDK policies. Rejected because absence would become an
  unsound negative. Rule-scoped evidence is accepted only when its own completeness is reported.
- Put TypeScript payload types into the generic store. Rejected because persistence must remain
  language-neutral and reusable by future analyzers.
- Infer comments and code in every text language heuristically. Rejected because plausible-looking
  counts are worse than explicit unclassified lines.
- Exclude binary, historical, or large files from repository statistics by default. Rejected because
  filters are projections and must not erase retained repository evidence.

## Compatibility, migration, and gate effects

These contracts remain pre-authority V2 changes. Existing databases migrate their snapshot-set
and capability materialization schema; caches remain regenerable. Fact envelopes and compiler
namespaces are unchanged. The typed reader is additive above generic queries. Scoped policies are
opt-in and global required-capability behavior remains fail-closed.

Gate 5 may proceed only through the application service and its pinned readers. Existing V1
authorities, tests, and transports are deleted only in the coordinated cut; this revision does not
authorize a mixed fallback. Gate 5 cannot complete until the specified operational limits are
measured and all consumers use V2. Gate 6 still requires the downstream extension, governed
self-hosting, package-delivered native binaries, performance evidence, and zero-V1 scans.

## Objections and dispositions

- Product objection: an application snapshot duplicates identifiers already present in its
  constituents. Resolved because it records coherent composition and lifecycle, not their semantic
  content, and gives every transport one stable generation handle.
- Analysis/native objection: typed readers could become a second validator that drifts from native
  wire admission. Resolved by versioning them at the public fact schema, validating only portable
  payloads after generic store integrity, and requiring the same adversarial native facts in Gate 6.
- Consumer/DX objection: rule-scoped completeness adds policy ceremony. Accepted because only
  policies that deliberately operate below global completeness pay the cost, and the explicit
  boundary prevents silent false negatives.
- Qualification objection: the self-host statistics run is not governed evidence. Accepted; it is
  diagnostic input only. The ledger does not advance self-hosting or performance requirements from
  that run.
- Performance objection: retaining large text may increase memory. Resolved by an explicit
  configurable per-source bound, one-source-at-a-time analysis, retained byte totals for binary or
  oversized inputs, and later measured Gate 5/6 ceilings.
- Maintainability objection: the application could absorb specification, analysis, or presentation
  logic. Resolved by contract laws: it composes immutable owners and leases; observations remain
  their own submodules and DTOs remain disposable adapters.

## Consensus and decision

Accepted before the Gate 5 authority switch under the user's explicit direction to build a
hierarchical, headless, reusable system above `ttsc`, preserve semantic contracts, avoid V1
overfitting, and govern careful consensus-driven revisions. No remaining perspective identified a
soundness, ownership, consumer, or qualification violation. Measured performance, package-native
delivery, the coordinated V1 deletion, and Gate 6 evidence remain open rather than being implied by
this decision.
