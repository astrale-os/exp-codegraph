# V2-REV-006: Keep compiler resolution and diagnostic evidence truthful

Status: accepted

Date: 2026-08-14

Affected requirements: V2-TS-001, V2-TS-015, V2-TS-021, V2-TS-022, V2-CON-001, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 4 treats V1 as an observational witness and requires every difference to be explained, while
TypeScript-Go is the selected V2 compiler authority. The first full 303-module comparison still
treated V1's selected external declaration file, declaration-anchor issue column, and unsupported
surface diagnostics as exact authorities. That would force V2 either to rewrite qualified compiler
evidence or to reproduce limitations already removed by its source-semantic normalizer.

## Proposed decision

- TypeScript-Go owns the exact declaration file selected for an import. Package ownership is a
  portable logical coordinate, but the selected provider file remains unmodified provenance.
- Gate 4 accepts an external target-file change only when one V1 edge and one V2 edge pair uniquely,
  both files belong to the same exact package coordinate, and source module, target owner, edge kind,
  source file, import spelling, flags, and occurrence location remain exact.
- An observation issue's semantic comparison key is code, message, source coordinate, and line. V2
  retains its exact native column, stable declaration join, and observed display value rather than
  replacing them with V1's coarser declaration anchor or positional identity.
- Frozen V1 unsupported issues disappear only for the exact enumerated declarations and shapes that
  V2 represents losslessly and the production-native fixture exercises. Any new, moved, or unmatched
  issue remains a Gate 4 failure.
- An expanded generic alias may bind a Checker-substituted type parameter by name only when exactly
  one active lexical binding has that name. Ambiguous nested scopes remain explicitly unsupported.
- Compiler diagnostics use the qualified ttsc driver's public root message. Gate 4 accepts only the
  one frozen TS2345 difference where V1 appends a Node-checker child message unavailable through the
  driver API; code, source, span, and root message remain exact and both strings are reported.

## Evidence and motivation

Six external relationships were identical except for compiler-selected declaration files:
TypeScript-Go selected package public declaration files where Node TypeScript selected `.d.cts`
entrypoints (and the reverse for Vitest's entrypoint layout). Rewriting those files would hide what
the resident compiler actually checked and would make future resolver upgrades impossible to audit.

The issue corpus contained identical code, message, file, and line with V2 pointing at the exact type
node rather than the containing declaration. V2 also retained the unsupported display value and can
join the flattened issue to a stable declaration ID. Eighteen V1-only issues were analyzer
limitations: supported primitive/object/symbol nodes, an index-signature composition, and a
compatible interface/namespace merge. One V2-only unbound `Descriptor` issue was not accepted as
drift; it exposed a real substituted-generic binding defect and is fixed with a unique lexical
binding rule plus an adversarial nested-alias fixture.

One Shell TS2345 diagnostic also showed that ttsc 0.26.2's public `driver.Diagnostic.Message`
contains the root TypeScript-Go message but not its internal child chain. The root message, code,
and exact span match. TypeSpec records this as a named upstream seam limitation rather than
recomputing diagnostics through a second compiler path or fabricating Node text.

## Alternatives

- Rewrite V2 target files to V1 paths. Rejected because it fabricates resolver output and may name a
  declaration file TypeScript-Go did not select.
- Compare only package names. Rejected because it would hide changes in source, kind, spelling,
  flags, locations, or ambiguous provider candidates.
- Copy V1 issue columns and omit V2 payload fields. Rejected because navigation and downstream
  analytics would become less precise, and positional declaration IDs are already rejected.
- Accept every missing unsupported issue. Rejected because an analyzer regression could silently
  erase a real incompleteness signal. The accepted list is exact and every removal is reported.
- Bind substituted parameters by spelling unconditionally. Rejected because shadowed generic names
  are common; only one active lexical candidate is safe.
- Re-run compiler diagnostics through TypeScript-Go internals to recover one child chain. Rejected
  because it duplicates ttsc's diagnostic filtering and preamble correction; the missing structured
  message-chain seam should be pursued upstream instead of silently forking compiler behavior.

## Compatibility, migration, and gate effects

Persisted shadow generations remain regenerable before Gate 5. Consumers gain truthful provider
provenance, precise issue navigation, stable issue-to-declaration joins, and fewer false-positive
unsupported diagnostics. No source module, package owner, dependency kind, import occurrence, issue
code, issue message, or source line is normalized away.

Gate 4 remains fail-closed. The resolver predicate requires a unique pair and emits both old and new
files. The issue predicate uses a frozen allowlist, proves the declaration remains in the V2 module
surface, reports every removed issue, and rejects every V2-only issue. Direct production-native cold
and incremental qualification remains mandatory after the normalizer change.

## Objections and dispositions

- Product objection: issue columns are observable CLI/editor behavior. Accepted as a defect
  correction because the V2 column points to the exact unsupported type while retaining file and
  line; presentations must use the V2 fact, not the parity projection.
- Analysis/native objection: two compiler generations may legitimately resolve different package
  declarations. Resolved by making the qualified compiler authoritative while retaining exact file
  evidence and an unusually narrow differential predicate.
- Consumer/DX objection: fewer warnings could look like lost coverage. Resolved by requiring
  lossless surface facts, declaration-presence proof, fixture coverage, and an enumerated drift
  report rather than a blanket suppression.
- Qualification objection: name-based generic recovery can be unsound. Resolved by accepting only
  one active lexical binding and keeping ambiguity unsupported.
- Consumer/DX objection: the TS2345 explanation is shorter. Accepted as one explicitly tracked ttsc
  seam gap; the diagnostic remains clickable and exact, and any second message difference fails.

## Consensus and decision

Accepted before authority cutover. The decision keeps TypeSpec as a headless layer above ttsc,
without adding a second resolver or cloning V1 analyzer defects. It strengthens evidence quality and
keeps the change inside the deeply nested TypeScript surface owner with cohesive flat leaf files.
