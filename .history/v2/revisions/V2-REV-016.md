# V2-REV-016: Separate compiler universes from requested analysis projections

Status: accepted

Date: 2026-08-15

Affected requirements: V2-ANA-001, V2-ANA-004, V2-ANA-006, V2-ANA-007, V2-ANA-012, V2-REP-004, V2-QLF-003, V2-QLF-006

Review perspectives: Codegraph product, analysis/native, consumer/DX, qualification/performance

## Existing decision

`V2-REV-010` correctly made the loaded compiler the authority for project-universe identity, but it
also included requested native capabilities and module-observation boundaries in that identity.
Those values select analysis projections; they do not change the TypeScript files, Checker
resolution, compiler options, or plugin semantics. As a result, requesting a shallow module catalog
and then a body graph for the same loaded project renamed every source, symbol, occurrence, shard,
and fact. The first demand-driven projection proof exposed this by showing payload-equivalent facts
with different portable identities.

## Proposed decision

- `ProjectUniverseId` describes only the compiler-semantic environment loaded by the native
  authority: the complete configuration chain, root and project-reference membership, compiler and
  plugin semantics, exact toolchain/protocol, and platform assumptions.
- Requested capabilities and module-observation boundaries are generation inputs. Capabilities are
  already explicit in `AnalysisGeneration`; module boundaries affect the content-addressed module
  facts and therefore the generation manifest when that projection is requested.
- A capability or module-boundary change may publish a complete generation in the same universe. It
  does not rename portable source, revision, symbol, occurrence, or body identities whose semantic
  inputs are otherwise unchanged.
- A native projection plan executes only requested projectors and their exact compiler
  prerequisites. Each emitted namespace must be byte-equivalent, after omitting only the enclosing
  generation binding, to the same namespace selected from an all-capability cold projection.
- Configuration, root membership, compiler/plugin semantics, toolchain/protocol, and platform
  changes retain the complete base-less universe-rollover behavior ratified by `V2-REV-010`.

## Evidence and motivation

On the adversarial projection microproject, all-capability and single-capability analyses loaded the
same TypeScript project and emitted the same semantic payload for the selected namespace, but the
requested capability set changed the universe preimage. Because source and symbol identities are
namespaced by that universe, the otherwise identical facts could not be joined. This defeats the
intended shallow-to-deep capability DAG and makes a cache key describe an execution plan rather than
the compiler project it caches.

The ADR vocabulary already defines a project universe as the compiler inputs that decide which
TypeScript files and semantics exist, while generations separately name their capability set and
complete manifest. The correction restores that layering rather than introducing a new identity or
store dimension.

## Alternatives

- Keep one universe per capability profile and normalize identities in consumers. Rejected because
  it makes stable source/symbol joins heuristic and duplicates one compiler project in repository
  snapshot sets.
- Add a separate public analysis-profile identity and key store current generations by both values.
  Rejected because generation capabilities and manifests already identify the projection exactly;
  another public identity would duplicate state and expand every query API.
- Force every consumer to request the richest native graph. Rejected because catalogs and
  dependency queries would continue paying for bodies, CFG, definition-use, and value inputs they
  never consume.
- Remove compiler/toolchain or platform inputs from the universe as well. Rejected because those
  inputs can change Checker semantics and must retain fail-closed lineage rollover.

## Compatibility, migration, and gate effects

Analysis stores are regenerable and require no schema migration. Existing generations whose
universe included projection inputs remain readable and pinned, while the next refresh publishes a
generation under the corrected compiler-derived universe. Generation, shard, and fact schemas are
unchanged.

Gate 2 identity and invalidation proofs gain a regression that selected namespace facts retain
exact portable identity across projection profiles. Gate 6 performance evidence must additionally
show that unrequested semantic projectors do not execute, ordinary shallow consumers do not hydrate
deep facts, and configuration/root changes still roll over and remain cold-equivalent. This
revision does not accept a performance threshold or advance diagnostic experiment evidence.

## Objections and dispositions

- Product objection: a module-boundary edit no longer creates a separate universe. Resolved because
  its resulting module facts and manifest produce a distinct immutable generation, while pinned
  readers retain the old observation.
- Analysis/native objection: two resident services could request different capability sets against
  one store current. Resolved at the existing transaction boundary: an initial session emits a
  complete snapshot and rebases it onto the destination universe; long-lived applications retain
  one resident service per compiler project and stale concurrent writers continue to fail closed.
- Consumer/DX objection: the current generation may contain a different capability set after
  another workflow refreshes it. Accepted because capabilities are explicit and queries are pinned;
  consumers must plan or request required capabilities rather than infer them from universe identity.
- Qualification objection: equal payload examples alone do not prove identity equivalence.
  Resolved by comparing exact fact envelopes without only the enclosing generation, exact shard
  references, emitted namespace sets, and native projector telemetry against an all-capability cold
  oracle.
- Performance objection: projection gating could merely filter output after a full walk. Resolved
  by requiring an exact phase allowlist and zero unrequested semantic projector events in the native
  proof.

## Consensus and decision

Accepted under the user's explicit direction to pursue the high-value demand-driven architecture
without over-engineering, preserve stable reusable identities, and govern material corrections
before relying on them. The product, native, consumer, and qualification perspectives agree that
projection selection belongs to the generation rather than the compiler universe; no remaining
objection demonstrates a soundness, compatibility, or Kernel-consumer violation.
