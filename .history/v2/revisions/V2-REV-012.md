# V2-REV-012: Make current Kernel ownership the conformance corpus

Status: accepted

Date: 2026-08-14

Affected requirements: V2-SPC-002, V2-TS-014, V2-TS-015, V2-TS-016, V2-TS-022, V2-CON-001, V2-CON-002, V2-MIG-003, V2-QLF-001, V2-QLF-009, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

Gate 4 originally treated the frozen 309-specification V1 repository catalog as the parity universe.
That was valid while the repository owned Kernel and downstream application specifications
together. It also required several narrow oracle exceptions for Admin and Shell compiler behavior
and for reverse dependency evidence introduced by the SDK closure.

The active origin/kernel-v2 branch now physically removes every .spec tree under Admin, Shell,
Issues, and Events. Those applications remain consumers of Kernel capabilities, but their deleted
contracts are no longer Kernel specification authority. The V1 artifact remains valuable historical
evidence; its old corpus boundary is not a reason to resurrect deleted ownership in V2.

## Proposed decision

- Current authored specification discovery defines the conformance authority. Gate 4 compares the
  immutable V1 witness only after projecting its catalog and verification rows onto those exact
  canonical sources.
- Projection is a generic set operation over source identities. It contains no application names,
  repository-layout allowlist, compiler project allowlist, or silent fallback.
- Historical V1 rows outside current authority stay in the immutable witness and are summarized by
  count and digest. A current source absent from V1 remains absent in the projected oracle and
  therefore surfaces through ordinary fail-closed comparison.
- V2 foundation specifications remain shadow inputs at Gate 4 and become self-analysis subjects at
  Gate 6. They do not acquire V1 history through projection.
- Admin-, Shell-, and SDK-closure-specific parity predicates are retired. If an equivalent
  difference reappears in the current Kernel corpus it is unexplained drift and fails.
- The governed graph remains closed over declared module vertices. That invariant belongs to the
  TypeScript semantic model; an unobserved historical reverse edge is not retained as a product
  exception.

## Evidence and motivation

Remote-tree inspection at 683ae7980ef07f4b8d36d6425bbbccc00c00fe41 found authored
specifications only below core, runtime, client, backend, dsl, server, protocol, ports, host, and
spec. Mirroring only the landed ownership deletion removed 582 downstream specification artifacts
without merging unrelated Kernel refactors.

A fresh production-native run after that deletion analyzed 144 TypeScript modules in ten compiler
universes. All nine module-parity dimensions qualified 144 of 144. The same run qualified without
the Admin diagnostic predicate, Shell message predicate, Shell verification policy, or external
unowned inbound predicate. Six current specification-only leaves remain explicit unobserved
authority, and V2's own foundation modules remain outside V1 parity for later self-analysis.

The oracle projection regression proves three distinct sets: retained historical sources, excluded
historical sources, and current sources absent from history. It preserves new-module detection
instead of manufacturing V1 catalog entries.

The Kernel-only comparison contains 262 raw differences, all byte-for-byte members of the prior 469
audited differences. The 207 removed witnesses are exactly 93 Admin, 37 Shell, 41 Issues, and 36
Events differences. The retained policy witnesses contain 223 coverage projections, 12 causal
unavailable-evidence projections, 20 corrected V1 findings, five diagnostic refinements, and two
status refinements, with no newly detected or unexplained finding.

## Alternatives

- Keep all 309 V1 entries authoritative. Rejected because it would make physically deleted
  downstream ownership part of the Kernel product and force V2 to preserve obsolete compiler and
  dependency quirks.
- Replace the frozen V1 artifact. Rejected because historical evidence should remain immutable and
  attributable; projection changes comparison scope, not recorded history.
- Hard-code Admin, Shell, Issues, and Events excludes in TypeSpec. Rejected because source authority
  is already expressed by authored files and the headless mechanism must work in other repositories.
- Pull or rebase the entire active Kernel branch during this work. Rejected because the dedicated
  V2 worktree carries broad uncommitted implementation changes; the ownership deletion can be
  mirrored independently and the final integration can resolve newer Kernel refactors explicitly.

## Compatibility, migration, and gate effects

Gate 3 and Gate 4 evidence must be regenerated for the current corpus before their prior completion
claims are relied upon. Gate 5 no longer migrates Admin, Shell, Issues, or Events specification
consumers inside this repository. It still migrates every Kernel package, CLI, server, watcher,
catalog, and viewer consumer and deletes all V1 authorities.

The historical oracle remains byte-for-byte available. Reports gain an explicit projection summary,
so auditors can distinguish current comparison, removed ownership, and new current sources.
Downstream projects may be indexed as separate declared repository universes in the future; they are
not silently imported into Kernel authority.

## Objections and dispositions

- Product objection: removing downstream specs reduces parity coverage. Accepted as an ownership
  correction; deleted contracts cannot be truthfully qualified as current Kernel products.
- Analysis/native objection: reverse SDK edges might be useful for impact analysis. Resolved by
  explicit multi-repository indexing and portable package facts, not anonymous vertices injected by
  a historical V1 traversal.
- Consumer/DX objection: application authors may still want TypeSpec. Accepted; the headless API is
  intentionally reusable, but each consumer supplies and owns its own authored corpus.
- Qualification objection: projection could hide an accidental deletion. Resolved by recording the
  exact excluded source count and digest, requiring an accepted scope revision, and keeping newly
  authored sources fail-closed.

## Consensus and decision

Accepted under the user's explicit direction to focus TypeSpec on Kernel .spec ownership and not
spend V2 effort reproducing deleted application contracts. Product ownership, compiler authority,
consumer reuse, and fail-closed qualification remain separated. The historical witness is
preserved, obsolete exception code is retired, and current source identity is the sole corpus
selector.
