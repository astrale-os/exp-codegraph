# V2-REV-027: Persist the workspace and propagate exact application deltas

Status: accepted

Date: 2026-08-16

Affected requirements: V2-ANA-005, V2-ANA-007, V2-APP-001, V2-APP-002, V2-APP-004, V2-APP-005, V2-CON-001, V2-CON-003, V2-CON-004, V2-MIG-002, V2-MIG-004, V2-MIG-007, V2-QLF-003, V2-QLF-006, V2-QLF-007, V2-QLF-009

Review perspectives: Codegraph product and API, analysis and invalidation, persistence and failure,
specification and conformance, CLI/viewer and agent DX, qualification and performance

## Existing decision

V2-REV-024 made one inventory-pinned application service authoritative and deliberately retained
only one process-local compiled corpus. It rejected a persistent application cache because the
authority cut did not yet require a second invalidation boundary. It also widened every declaration
edit outside `.spec` to the complete specification corpus because the application did not own a
reverse declaration-dependency index.

That decision removed duplicate work inside one process, but it did not address either process
restart or the complete application delta. On the 320-specification Kernel corpus, an unchanged
new process required 244,924 ms before the viewer became ready. A one-specification projection after
editing `.spec/api.d.ts` still took 43,897–48,278 ms because the projection counter hid complete
normative recompilation followed by repository-wide observation and qualification work.

## Decision

- Codegraph owns a reusable headless workspace lifecycle below specification, conformance, CLI,
  server, viewer, and future semantic-pack consumers. It selects exact repository inventory and
  immutable analysis generations; it owns no `.spec`, Vite, HTTP, or presentation semantics.
- A durable workspace checkpoint is advisory evidence, never semantic authority. It names the exact
  repository inventory, request and producer fingerprints, universe-to-generation mapping, and
  content-addressed derived artifacts. Facts remain authoritative in the analysis store.
- A new process validates checkout topology and file metadata, hashes every uncertain or changed
  candidate, and reopens the exact pinned generations. A missing, stale, corrupt, incompatible, or
  pruned checkpoint takes the ordinary cold path without publishing partial state.
- A filesystem change set is normalized to canonical root-relative POSIX paths and resolved against
  old and new ownership. Caller-supplied paths are hints. When exact ownership or reverse dependency
  closure cannot be proven, refresh widens visibly to a conservative full result.
- Specification compilation owns a content-derived input and reverse-dependency index covering
  authored resources, declaration dependencies, aliases and barrels, source references, package
  authority, and project configuration. A local resource changes one owner; a public declaration
  changes its exact transitive dependent closure rather than the complete corpus.
- Repository statistics retain per-file results only when source revision and analyzer identity are
  unchanged, then recompute the exact complete summaries and arbitrary groupings for the new
  inventory. Observation facts retain unchanged owner shards without reload or rewrite.
- Qualification reuse requires both an exact unchanged owner/dependent impact and a profile manifest
  declaring specification-local evaluation. The outer qualification is rebound to the current exact
  analysis snapshot and re-identified. Universe-scoped, custom, changed-request, or uncertain inputs
  are conservatively re-evaluated.
- Verification is a revision-bound qualification projection, not a process-local source flag. Its
  catalog publication is atomic and its advisory record is accepted only for the same specification
  revision and exact owner/dependency input fingerprint. Page reload performs no analysis; relevant
  owner/dependency changes refresh a bounded resident verifier while leaving the full viewer
  application on its cheaper local profile set.
- Checkpoint manifests remain small and reference independently bounded content-addressed artifacts.
  A bounded number of named scopes may be retained; rolling catalog and inventory scopes replace
  their prior manifest, and unreachable artifacts are pruned best-effort. Reads never rewrite
  semantic products.
- Ordinary CLI and agent commands reuse this lifecycle automatically; Codegraph does not add public
  `index`, `cache`, or `daemon` namespaces merely to expose implementation mechanics.

## Evidence and motivation

The existing SQLite store already provides immutable generations, leases, content-addressed shards,
and exact snapshot-set identities. Resident ttsc sessions already provide affected compiler closure.
The missing work is above and around those boundaries: generation discovery after restart, durable
derived-product references, project routing, and owner-level delta propagation.

The new design does not serialize one repository-sized application snapshot and does not duplicate
fact payloads. It persists a small self-validating manifest plus independent specification,
  statistics, qualification, and optional bounded catalog artifacts. The application checkpoint is
  independent of the catalog checkpoint, so headless consumers never hydrate presentation data.

## Alternatives

- Keep raising heap limits or accept a four-minute restart. Rejected: neither addresses repeated
  semantic work and both make CLI, agent, and viewer use impractical.
- Add persistence only inside the dev server. Rejected: CLI, agents, linters, and future semantic
  packs need the same workspace, while Vite must remain a consumer rather than lifecycle authority.
- Run a daemon and make it authoritative. Rejected: a daemon is unnecessary for durable reopen and
  would add process coordination before a concrete consumer requires it.
- Trust changed-path hints without repository validation. Rejected: dropped events or incomplete
  callers could retain stale facts and turn missing evidence into false qualification.
- Persist one complete nested JSON application snapshot. Rejected: it recreates the previous
  repository-sized snapshot representation, broad hydration, and large parse allocation.
- Require a long counterbalanced performance matrix. Rejected: exact cold equality plus causal
  work/byte counters and short isolated trials answer the architecture question more directly.

## Compatibility, migration, and gate effects

The analysis generation and fact contracts remain unchanged. Snapshot sets add their exact
universe-to-generation mapping, which was already part of their identity preimage. Existing cache
formats are regenerable and invalidated rather than migrated.

The current TypeSpec-named application surface remains during the incremental package rename, while
new foundational APIs use Codegraph terminology. Kernel's `pnpm spec dev` journey and viewer remain
available as first-party consumers. Removed product Domain specifications and retired V1/e2e
authorities are not restored.

Rollback remains source-control revert plus removal of regenerable checkpoint artifacts. The cold
path is the same semantic authority, not a compatibility reader or dual-write mode.

## Qualification

- An unchanged Kernel restart must become viewer-ready within 10,000 ms, perform zero compilation,
  native extraction, observation, qualification, projection, generation commits, or artifact
  payload writes, and reproduce the exact application and catalog identities.
- An ordinary one-owner specification edit must complete within 5,000 ms and report causal counters
  equal to the exact owner/dependent closure. Unaffected artifacts are neither loaded nor rewritten.
- Incremental edit, create, delete, rename, package, declaration, configuration, and branch-like
  sequences must normalize to the same inventory, facts, observations, statistics, qualifications,
  verification, and catalog as an independent cold build.
- Browser page refresh triggers no workspace refresh. Repeated no-op restarts and twenty edit/revert
  cycles retain bounded snapshots, generations, artifacts, processes, database bytes, and memory.
- Cold behavior is recorded with at most short isolated causal comparisons. An unexplained cold
  regression above five percent blocks graduation; noisy whole-repository matrices are not a gate.

## Objections and dispositions

- Objection: a persistent checkpoint becomes a second authority. Rejected because publication
  requires exact inventory, producer, protocol, generation existence, and content-digest validation;
  every rejection executes the same cold authority and no checkpoint can fabricate facts.
- Objection: precise application invalidation duplicates ttsc. Rejected because ttsc remains
  compiler authority. The application adds only ownership of its specification, observation,
  qualification, and presentation artifacts, which ttsc does not model.
- Objection: profile scope constrains extension authors. Accepted as intentional: an extension may
  omit the declaration or choose universe scope, but it then receives conservative re-evaluation
  rather than claiming precise incremental reuse.

## Consensus and decision

Accepted by the maintainer after application/incremental and lifecycle/persistence reviews. The
decision preserves V2 semantic authority, exact cold equality, and the thin specification spine
while correcting the two user-visible lifecycle defects with one reusable workspace foundation.
