# V2-REV-011: Keep inbound module relationships inside the governed graph

Status: accepted

Date: 2026-08-14

Affected requirements: V2-TS-014, V2-CON-001, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

V2 module dependencies have content-derived logical identities, complete occurrence evidence, and
exact source and target modules. Inbound relationships are the inverse view of those governed
outbound facts. V1 remains an observational witness, but known V1 defects are tracked and corrected
rather than reproduced.

During cold Kernel qualification, V1 added inbound relationships whose `sourceModule` was an
absolute `unowned:` SDK source path. Those relationships did not occur in any catalog module's
outbound dependencies because no catalog module owned their source files.

## Proposed decision

- The governed module graph contains only edges whose source and target vertices are governed
  modules. An external package may appear as a package target or declaration provider, but its
  internal files do not become anonymous module vertices.
- Parity accepts a missing V1 inbound edge only when the source module is explicitly `unowned:`, is
  absent from the complete governed module set, and the physical source resolves to a portable
  `package:` coordinate. Every accepted relationship is enumerated with portable source, target,
  kind, specifier, and target file.
- A missing edge from a governed module, an unportable source, or a non-package source remains
  unexplained drift and fails qualification.

## Evidence and motivation

A coherent SDK overlay made both Node TypeScript and TypeScript-Go resolve the same SDK and Kernel
sources. Source-side dependency parity qualified for all 303 modules, while V1 alone injected 13
external SDK occurrences into nine Kernel modules' inbound lists. Mapping each content-derived
failure ID proved that every source was an unowned SDK file and that no corresponding governed
outbound edge existed.

The focused predicate regression rejects a governed source and an unowned non-package source. The
full cold parity report records the exact accepted relationships without absolute paths.

## Alternatives

- Reproduce the V1 inbound list. Rejected because inbound and outbound queries would disagree and
  absolute checkout topology would leak into the logical graph.
- Promote every external source file to an anonymous module. Rejected because module ownership and
  completeness would be undefined and package internals would become accidental product API.
- Drop all unowned dependencies. Rejected because genuinely missing governed edges must fail, and
  portable package relationships remain valuable evidence.
- Normalize the source into the importing Shell module. Rejected because that would falsely claim
  ownership of SDK implementation imports.

## Compatibility, migration, and gate effects

No V2 fact or query schema changes. Consumers gain the invariant that every inbound relationship can
be joined to one governed source module's outbound relationship. The correction affects only the V1
parity witness and is recorded as V2-DRIFT-021. Gate 4 must rerun from a fresh native checkpoint and
retain the enumerated correction evidence.

## Objections and dispositions

- Product objection: omitting SDK-to-Kernel imports may hide impact. Resolved by package and public
  closure facts for governed modules; indexing the SDK itself requires declaring it as another
  governed repository/module universe, not inventing anonymous vertices.
- Analysis objection: `unowned:` may mask target-discovery bugs. Resolved by additionally requiring
  absence from the complete governed set and a portable package source coordinate.
- Consumer/DX objection: cross-repository impact needs a future graph. Accepted; the headless model
  supports composing explicitly indexed repositories, while this correction preserves truthful
  ownership today.
- Qualification objection: an environment-specific path could be accepted. Resolved because the
  predicate records only package coordinates and rejects non-package or governed sources.

## Consensus and decision

Accepted as a narrow V1 defect correction. The governed graph remains closed over declared module
vertices, external package evidence remains attributable, and unexplained relationship loss remains
fail-closed.
