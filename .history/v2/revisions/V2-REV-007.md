# V2-REV-007: Prove lexical bindings and keep corpus evidence single-source

Status: accepted

Date: 2026-08-14

Affected requirements: V2-TS-015, V2-TS-022, V2-CON-001, V2-QLF-004, V2-QLF-011

Review perspectives: TypeSpec product, analysis/native, consumer/DX, qualification

## Existing decision

V2 preserves authored generic structure and treats unsupported results as explicit completeness
evidence. Gate 4 compares a complete native corpus with V1 while treating V1 as an observational
witness rather than semantic authority. The first 303-module replay used checkpoints that retained
the same module payload once as a module map and again inside authoritative transactions.

The qualified native correction for unique lexical generic bindings removed additional V1
unsupported warnings. The existing supported-surface drift predicate could not accept a module that
mixed those corrections with already-qualified representation corrections, and it proved only that
the declaration survived—not that the corrected parameter binding survived inside it.

## Proposed decision

- A generic reference binds by spelling only when one exact active lexical binding owns that name.
  The portable fact retains the binding's scope and index; a constraint never substitutes for the
  parameter itself. Shadowed or otherwise ambiguous names remain unsupported.
- Gate 4 accepts a removed V1 lexical-binding issue only when its code, message, source, line,
  parameter name, and declaration are in the frozen correction set, and the retained V2 declaration
  contains both that named scope/index binding and a matching parameter reference.
- Independently qualified correction classes may coexist within one module, but every missing issue
  must satisfy one named predicate and every V2-only issue still fails.
- Full-corpus V4 checkpoints store validated native transactions as their sole fact authority.
  Sorted module identities and a content digest are derived from those transactions and verified on
  every resume or conformance replay; module payloads are never duplicated in the checkpoint.
- The corpus harness may explicitly raise the native transport frame ceiling to 256 MiB for a
  measured complete Runtime project transaction. The reusable process adapter keeps its 64 MiB
  default, and a future chunked protocol may replace this bounded qualification exception without
  changing facts, stores, or consumers.

## Evidence and motivation

The complete ttsc 0.26.2 / TypeScript-Go 7.0.2 run produced 303 modules across 15 projects. Eight
parity dimensions were exact for all 303 modules. The remaining three modules contained only 17
additional V1 false-positive issues for correctly retained generic bindings, mixed with nine
previously qualified surface corrections in one Core module. The corrected shapes include nested
interface-method parameters, conditional aliases, conditional callable returns, indexed access,
and constrained parameters. The production fixture exercises each ownership form and rejects both
constraint collapse and unsupported output.

The V3 checkpoint failed after Runtime with `RangeError: Invalid string length`: every module fact
was serialized twice, even though retained transactions were already the commit authority. The V4
checkpoint completed all 15 transactions and 303 modules at roughly half the serialized size while
retaining an exact module index and digest. Memory and SQLite then replayed the same transactions and
produced identical per-universe exported fact streams.

## Alternatives

- Reproduce V1's generic warnings. Rejected because it would label an exact lexical parameter as
  unknown and could collapse it to its constraint.
- Accept every missing unsupported issue. Rejected because it would turn analyzer regressions into
  silent apparent improvements.
- Keep separate supported-surface and lexical branches that each require the whole module delta.
  Rejected because independent corrections can legitimately coexist; classification belongs to
  each issue, not to an entire module.
- Raise the JavaScript string or heap limit while preserving duplicate checkpoint payloads.
  Rejected because duplication has no semantic value and scales with the largest project.
- Lower the global native frame limit by truncating a project transaction. Rejected because one
  atomic project generation must remain complete. Protocol chunking is a transport evolution, not
  permission to split semantic authority.

## Compatibility, migration, and gate effects

This changes only shadow evidence before Gate 5. Consumers receive more precise generic type facts
and fewer false warnings; remaining unsupported infer bindings stay visible. V1-to-V2 issue drift is
enumerated rather than normalized out. V1-V3 diagnostic checkpoints remain readable for resume, but
full-corpus conformance requires complete V4 transaction-authoritative evidence.

The checkpoint format is qualification infrastructure rather than a public persistence contract.
Memory and SQLite continue to consume the same `FactTransaction` API, and module facts keep their
existing identities and schemas.

## Objections and dispositions

- Product objection: fewer warnings may conceal lost coverage. Resolved by exact frozen matching,
  retained-declaration proof, and separate reporting for every correction.
- Analysis/native objection: name-based binding can be unsound under shadowing. Resolved by requiring
  one active lexical binding and persisting its scope and index; ambiguity remains unsupported.
- Consumer/DX objection: issue-level correction classes complicate reports. Resolved by emitting a
  compact per-class summary plus the complete enumerated evidence in machine-readable output.
- Qualification objection: transactions alone make module inspection inconvenient. Resolved by a
  verified derived module index on read, without storing a second payload authority.
- Scalability objection: a 256 MiB frame is still large. Accepted as a measured bounded corpus seam;
  the generic adapter remains conservative and chunking stays an internal protocol improvement.

## Consensus and decision

Accepted before Gate 4 authority evidence is written. The decision keeps TypeSpec above ttsc,
strengthens fail-closed issue proof, and removes qualification-only duplication without leaking the
corpus workaround into the reusable headless API. It preserves the deeply hierarchical module
architecture while keeping the native surface and conformance leaf modules cohesive and flat.
