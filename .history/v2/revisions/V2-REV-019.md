# V2-REV-019: Recompose module facts from affected semantic owners

Status: accepted

Date: 2026-08-15

Affected requirements: V2-ANA-014, V2-QLF-006

Review perspectives: Codegraph product, TypeScript invalidation, module semantics, persistence, qualification/performance

## Existing decision

Compiler-proven private edits reproject source-owned symbol, occurrence, and body shards, but the
native adapter conservatively rebuilds every monolithic `astrale.typescript.module` fact and the
project-wide diagnostic shard. This preserves exact cold equivalence but makes Kernel private edits
15.4 seconds even when one source and fewer than twenty semantic shards change.

The public module fact is valuable and must remain one complete consumer-facing observation. Its
surface, dependencies, diagnostics, packages, files, error codes, issues, and evidence cannot be
silently made partial merely to accelerate the physical projector.

## Proposed decision

- A compiler-proven private edit reprojects only module boundaries that semantically own an affected
  source. The resulting public module fact remains byte-identical to the same module in a complete
  cold projection.
- The resident generation retains canonical outbound module dependencies as private recomposition
  state. Rebuilding one target module combines current syntax/public edges from selected owners with
  retained outbound edges from unchanged owners, preserving exact inbound dependency closure.
- Diagnostic invalidation fingerprints exact diagnostic semantics and the revision of every selected
  source contributing diagnostic evidence. A diagnostic that keeps its message and offset across an
  edit still changes when its attributable source revision changes.
- Declaration-shape changes, dependency-projection changes, global diagnostic changes, root or
  configuration churn, imports, ambient scope, linked mutating plugins, and any uncertain closure
  continue to select every module or the complete compiler projection.
- Project facts remain carried within a stable compiler universe. Native transport and application
  materialization still publish only changed shard upserts and deletes through commit-late
  acknowledgement.

## Evidence and motivation

The first Kernel holdout reprojected one source but still took 15,358 ms versus a 28,360 ms cold
oracle. This disproved the assumption that globally rebuilding module observations was cheap.

The first owner-selective candidate ran in 805 ms but failed exact cold equality. Its exact witnesses
identified two generic defects: diagnostic evidence retained the previous source revision when the
diagnostic offset was unchanged, and a selected module retained 31 syntax inbound dependencies while
the cold fact contained 70 after public-API inbound closure. The accepted candidate fixes both causes
without repository or module exceptions.

Current diagnostic results on the same implementation and native binary are:

| Corpus | Private edit | Independent cold | Ratio | Projected scope | Exact cold generation |
| --- | ---: | ---: | ---: | --- | --- |
| Codegraph | 996.99 ms | 88,031.74 ms | 88.30x | 1 source, 1 module | yes |
| Kernel core | 826.69 ms | 24,709.47 ms | 29.89x | 1 source, 1 module | yes |

The Kernel candidate sends 886,090 wire bytes and allocates 472,392,776 bytes cumulatively, compared
with 4,261,368,112 bytes in the rejected global-module candidate. These are diagnostic runs, not
governed release evidence or substitutes for the frozen counterbalanced qualification.

## Alternatives

- Split the public module fact into surface, dependency, diagnostic, and inventory facts now.
  Rejected because internal owner-selective recomposition reaches the edit target without imposing a
  premature public migration. A later semantic split remains possible if independent consumers need
  those capabilities.
- Reuse every module fact when declaration shape is unchanged. Rejected because private bodies can
  change error codes, computed dependencies, diagnostic evidence, and source locations.
- Accept temporary stale module facts and refresh them asynchronously. Rejected because an exposed
  generation must be exact and immutable; eventual repair would violate cold equivalence.
- Rebuild only the changed owner without retained cross-owner edges. Rejected by the Kernel witness:
  inbound public-API dependencies are produced by unchanged source modules.

## Compatibility, migration, and gate effects

There is no public API, fact schema, namespace, identity preimage, SQLite schema, or native protocol
change. The resident process gains private generation-local recomposition state; a restart without
that state performs the existing conservative complete projection.

Gate 6 must retain exact adversarial proofs for private bodies, source diagnostics, computed dynamic
dependencies, public shapes, static imports, ambient/global scope, create/delete/rename,
configuration, linked plugins, and failed-commit replay. Codegraph and Kernel repeated measurements
remain diagnostic until the frozen counterbalanced and SQLite no-rewrite qualification completes.

## Objections and dispositions

- Module-semantics objection: retained edges could become stale. Resolved by replacing every edge
  whose source module is reprojected and selecting all modules whenever the dependency fingerprint
  changes.
- Diagnostic objection: equal message/offset does not imply equal evidence. Resolved by including the
  selected source text digest in the fingerprint whenever that source contributes a diagnostic.
- Persistence objection: private resident caches cannot become durable authority. Accepted; the
  cache only avoids recomputation inside one acknowledged lineage. Facts and manifests remain the
  sole published authority, and restart falls back safely.
- Qualification objection: the fast first candidate was unsound. Accepted and retained as a
  negative design witness; only the corrected exact-cold runs are reported as current diagnostics.

## Consensus and decision

Accepted as an internal ownership correction under the existing affected-source law. It removes a
measured repository-sized projector while preserving the complete public module fact and every
conservative fallback.
